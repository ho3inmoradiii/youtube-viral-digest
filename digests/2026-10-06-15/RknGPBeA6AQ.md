## خلاصه

راوی Paperclip را لایهٔ بالای ایجنت می‌داند. Claude Code و Codex هنوز کد می‌نویسند. Paperclip تسک می‌سازد، کار را بین ایجنت‌ها رد می‌کند، و سابقه را نگه می‌دارد. آداپتر را اتصال شروع ایجنت و جمع نتیجه می‌خواند و Claude Code و Codex و Gemini CLI و Cursor و OpenCode و Pi را اسم می‌برد. README همین ریپو آداپتر را Claude Code و Codex و CLIهایی مثل Cursor و Gemini و bash و بات HTTP مثل OpenClaw می‌داند. این دو فهرست را یکی نکردم.

مثال خودش اپ نوت محلی است: ساختن، ویرایش، حذف، و ماندن نوت بعد از رفرش. حساب و پرداخت را بیرون از نسخهٔ اول می‌گذارد. تیم نمونه: هماهنگ‌کننده، کدنویس، بازبین. می‌گوید برای این دمو شش مدیر لازم نیست. اگر استراتژی، بک‌اند و احراز هویت خواست، باید برگردد. تمام‌شدنِ ایجنت را شروع بازبینی می‌داند و می‌خواهد اپ را ببیند و نتیجهٔ تست را بخواند.

دستور نصب در گفتار به‌هم ریخته شنیده شد. README دستور را `npx paperclipai onboard --yes` می‌نویسد و می‌گوید PostgreSQL توکار ساخته می‌شود. نسخهٔ Node در `package.json` با «۲۴٫۱۱ یا جدیدتر» گفتار می‌خواند.

ضربان تایمر برای ایجنت تازه خاموش است. هم گفتار این را می‌گوید و هم سند [Heartbeats and Routines](https://docs.paperclip.ing/guides/projects-workflow/routines/). مثال سند: پنج ایجنت که هر پنج دقیقه بیدار شوند، بعد از یک ساعت شصت اجرا که بیشترشان کاری برای انجام ندارند. ترکیب پیشنهادی سند: تایمر خاموش، بیدار شدن با واگذاری روشن.

checkout در همان سند است. `POST /api/issues/{issueId}/checkout`. اگر ایجنت دیگر مالک تسک باشد، پاسخ `409 Conflict` است و نباید دوباره زده شود. راوی جدا می‌گوید دو تسک هنوز می‌توانند یک کد را لمس کنند. سند ورک‌اسپیس این شکاف را باز می‌گذارد. صفحهٔ [Execution Workspaces](https://docs.paperclip.ing/guides/projects-workflow/workspaces/) همان اول می‌گوید ورک‌اسپیس آزمایشی است و تا وقتی در تنظیمات نمونه روشن نشود، صفحه پنهان است. حالت «Project primary workspace» روی checkout اصلی پروژه کار می‌کند، نه روی کپی جدا، و تغییر مستقیم به همان کپی مشترک می‌رسد. حالت isolated یک git worktree تازه از ref پایه می‌سازد. جملهٔ «experimental» مال خود سند است، نه فقط صفت راوی.

بودجه را راوی تضمین صورتحساب نمی‌داند، چون اجرا روی خرج ثبت‌شده است و کارِ در جریان می‌تواند توقف را عقب بیندازد. صفحهٔ [Costs](https://docs.paperclip.ing/guides/day-to-day/costs/) دو پله می‌گوید: هشدار در ۸۰ درصد و ادامهٔ کار، مکث در ۱۰۰ درصد و نرفتن ضربان بعدی. تسک‌های در جریان assign می‌مانند تا ایجنت دوباره روشن شود. همان صفحه یک جملهٔ بازاری هم دارد که ایجنت یک سنت از سقف آن‌طرف‌تر نمی‌رود. صفحهٔ [Costs API](https://docs.paperclip.ing/reference/api/costs/) می‌گوید آداپتر معمولاً بعد از تمام شدن ضربان خرج را ثبت می‌کند و بعد سیاست بودجه ارزیابی می‌شود. برجستهٔ جست‌وجوی صفحهٔ how-to می‌گفت اجرای در جریان لغو می‌شود. این جمله با «تسک assign می‌ماند» در صفحهٔ Costs یکی نیست و وارد پست نشد.

کنترل اکشن در درگاه ابزار Paperclip را راوی از مجوز شل خود ایجنت جدا می‌کند. این تفکیک را در سندی که این اجرا خواند خط‌به‌خط ندیدم و وارد پست نشد. Skill Studio و روتین هفتگی هم در گفتار هست و پست نگرفت.

## نکته‌های کلیدی

- دستور نصب قابل‌استناد `npx paperclipai onboard --yes` است. Node از `package.json` برابر `>=24.11.0` است
- تایمر پیش‌فرض خاموش است. مثال سند: پنج ایجنت، هر پنج دقیقه، شصت اجرای یک ساعت
- checkout تسک با ۴۰۹ قفل می‌شود. checkout مشترک کد را قفل نمی‌کند. worktree مال حالت isolated و ویژگی آزمایشی است
- سقف ۸۰ و ۱۰۰ از صفحهٔ Costs است. ترتیب ثبت خرج، بعد از ضربان است. لغو اجرای در جریان با ماندن تسک در یک پست قاطی نشد
