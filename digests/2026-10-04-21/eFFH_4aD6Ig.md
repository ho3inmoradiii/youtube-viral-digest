## خلاصه

جیمز کوئیک Vinext را پلاگین متن‌باز Vite از کلودفلر می‌گوید که سطح API نکست را روی Vite از نو ساخته. گفت کارمند کلودفلر است و سوگیری دارد. شروع را آزمایش آخر هفتهٔ یک مهندس با یک دسته توکن دانست، هفت ماه پیش، و حالا ۱٫۰. بلاگ ۲۸ سپتامبر ۲۰۲۶، به قلم جیمز اندرسون و مت «TK» تیلور، همان را دقیق‌تر می‌گوید: آزمایش یک‌هفته‌ای در فوریه برای بازسازی نکست روی Vite، و هفت ماه بعد چارچوبی که می‌گویند مشتری پرترافیک در تولید اجرا می‌کند.

دستورها را `npx vinext check` و `npx vinext init` گفت. بلاگ برای اپ تازه `npm create vinext-app@latest` را هم دارد و برای استقرار با گرم‌کردن کش `npx @vinext/cloudflare deploy --warm-cache`.

سازگاری تست را «۹۹ درصد روی Pages و App Router» گفت و قید کرد مال قابلیت‌هایی است که مشتری خواسته. بلاگ دو جمله دارد: برای مهم‌ترین قابلیت‌های درخواستی مشتری حالا از ۹۹ درصد گذشته، و سازگاری تست به بیش از ۹۹ درصد رسیده، به‌جز Cache Components. README ریپو جدا می‌گوید حدود ۹۴ درصد سطح API نکست ۱۶ پوشش کامل یا جزئی دارد و شکاف باقی‌مانده را stub قابلیت منسوخ به‌علاوهٔ Partial Prerendering و Cache Components می‌داند. این دو درصد را یکی نکردم.

هر دو روتر را پشتیبانی‌شده گفت: کامپوننت سرور، Server Action، مسیر API، route handler، میان‌افزار، ناوبری کلاینت، و ISR. بلاگ همان فهرست را دارد و می‌گوید Pages Router هنوز برای مشتری مهم است چون مهاجرت یک قدم نیست. کوئیک دلیل را همین دانست: نکست سریع پارادایم عوض می‌کند و اپ بزرگ وسط کار روزانه جابه‌جا نمی‌شود.

Cache Components و دستور `use cache` را پشتیبانی‌نشده گفت، چون بیشتر تیم‌هایی که کلودفلر باهاشان حرف زده از آن استفاده نمی‌کردند و پشتیبانی را پیش‌شرط جابه‌جایی نمی‌دانستند. بلاگ می‌گوید پشتیبانی امروز محدود است و تمرکز جای دیگری است. README دقیق‌تر است: `use cache` برای سطح فایل و تابع پیاده شده، ولی رفتار کامل `cacheComponents` هنوز ناقص است، از جمله پروفایل و تگ و پوستهٔ جزئی. در پست «پشتیبانی محدود» را از بلاگ آوردم، نه «اصلاً نیست» را از جمع‌بندی ویدیو.

تفاوت با OpenNext را این‌طور گفت: OpenNext خود نکست است به‌علاوهٔ آداپتر خروجی؛ Vinext پیاده‌سازی دوبارهٔ سطح API روی Vite است و صد درصد API را ندارد. اگر پوشش کامل لازم باشد OpenNext را نزدیک‌تر دانست. بلاگ مسیر OpenNext را برای اپی می‌گذارد که به‌خاطر شکاف سازگاری هنوز نمی‌تواند به Vinext بیاید. این توصیه را از ویدیو آوردم و به‌عنوان بنچمارک اندازه نگرفتم.

گرم‌کردن کش را از ماشین بیلد به شبکهٔ کلودفلر برده‌اند. بلاگ می‌گوید نسخهٔ تازهٔ Worker با صفر درصد ترافیک تولید بالا می‌آید، صفحه از همان نسخه درخواست می‌شود، و بعد از پر شدن کش استقرار ارتقا می‌یابد. Vinext می‌تواند صفحهٔ پرترافیک را هم به فهرست ازپیش‌رندر اضافه کند. کوئیک گفت بده‌بستان زمانی را هنوز کامل نفهمیده. همان ابهام را در پست به‌عنوان اندازه‌گیری زمان نیاوردم.

API گیت‌هاب در همین اجرا برای `cloudflare/vinext` عدد ۹۰۸۷ ستاره و `pushed_at` برابر `2026-10-02T16:00:41Z` داد. تازه‌ترین انتشار `vinext@1.0.1` در `2026-10-01T14:16:32Z` بود.
