# Vite and Module Federation Makes Micro-Frontends EASY!

- **کانال:** Jack Herrington
- **بازدید:** 138,996
- **مدت:** حدود ۲۸ دقیقه
- **موضوع:** Microfrontend shared state routing

## خلاصه

Herrington تفاوت اشتراک زمان بیلد و اشتراک runtime را با یک هدر بین صفحه خانه و صفحه محصول نشان می‌دهد. در مدل کتابخانه‌ای، هر دو اپ پکیج را import می‌کنند و برای هر تغییر هدر هر دو باید deploy شوند. در Module Federation، صفحه خانه هدر را expose می‌کند و صفحه محصول همان را در runtime می‌گیرد؛ یک deploy ریموت برای همه مصرف‌کننده‌ها کافی است. این برد معماری را مخصوص فضای شرکت بزرگ می‌داند که چند تیم باید UX یکسان داشته باشند.

دمو با پلاگین federation روی Vite است: اپ remote و اپ host، پورت سخت‌گیرانه‌ی 5001 تا URL ریموت نپرد، و یک دکمه شمارنده. نکته‌ای که وسط دمو بیرون می‌زند مهم‌تر از خود پلاگین است. شمارنده روی پورت ۵۰۰۱ و شمارنده روی هاست عددهای متفاوت دارند. فدراسیون کد را share می‌کند، نه state را. اگر state مشترک می‌خواهی، باید خودت مکانیزم بیاوری.

پیشنهاد او برای سطح تماس کوچک (شناسه کاربر، محتوای سبد) state اتمی است، اینجا Jotai: یک atom و یک هوک useCount که هم از ریموت expose می‌شود هم در هاست مصرف می‌شود، و خود Jotai هم باید در تنظیم share باشد. دلیل رد Redux و Zustand برای این مرز: با استور یک‌پارچه، افزودن فیلد جدید اصطکاک ندارد و کوپلینگ بی‌صدا رشد می‌کند. با اتم، هر داده مشترک یک تصمیم آگاهانه است.

سازگاری Webpack 5 با ریموت Vite/Rollup هم نشان داده می‌شود، به قیمت تنظیم output ماژول و script type=module. در پایان مونوریپو Turborepo همان دکمه و همان استور را در زمان بیلد share می‌کند. مزیت بیلد: TypeScript، تست واحد، و یک بسته منسجم بدون وابستگی runtime. عیب: با هر تغییر باید مصرف‌کننده را هم منتشر کنی. عیب runtime برعکس است: تایپ در مرز گم می‌شود، تست واحد ماژول غایب را نمی‌بیند، و ریموت می‌تواند هاست را در پروداکشن بشکند بدون این‌که بیلد هاست قرمز شود.

## نکات کلیدی

- اشتراک runtime یعنی یک deploy برای هدر؛ اشتراک بیلد یعنی هر مصرف‌کننده باید دوباره منتشر شود.
- دو اپ که یک کامپوننت را می‌گیرند، state جدا دارند مگر خودت استور را هم share کنی.
- سطح تماس state را کوچک نگه دار. اتم این اصطکاک را اجباری می‌کند؛ استور گلوبال نه.
- ریسک اصلی runtime این است که شکست را از زمان بیلد به زمان بازدید کاربر منتقل می‌کنی.

## برش کوتاه

> این‌جا جادو نیست. فقط کد را share می‌کنیم. اگر state می‌خواهی، باید خودت جایش را بسازی.

> هرچه داده بیشتری بین هاست و میکروفرانت رد و بدل شود، کوپلینگ سفت‌تر می‌شود. اتم مجبورت می‌کند برای هر قلم تازه تصمیم بگیری.
