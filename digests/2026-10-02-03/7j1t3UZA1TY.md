## خلاصه

ویدیو از نیاز مدل به داده و ابزار بیرونی شروع می‌کند. تا پیش از این، راه پیش‌فرض API بود. اواخر ۲۰۲۴ انتروپیک Model Context Protocol را به‌عنوان استاندارد باز معرفی کرد. استعاره اصلی USB-C است: لپ‌تاپ (میزبان MCP) چند کلاینت دارد، هر کلاینت یک نشست JSON-RPC 2.0 باز می‌کند، و سرورها مثل مانیتور و دیسک و شارژر به همان درگاه می‌خورند؛ سازنده وسیله مهم نیست.

میزبان برای عامل دو چیز می‌خواهد: زمینه (سند، رکورد، دانش) و ابزار (جست‌وجو، سرویس، محاسبه). سرور سه نوع قابلیت را آگهی می‌کند. Tools کارهایی مثل گرفتن آب‌وهوا یا ساختن رویداد تقویم‌اند، با اسم و توضیح و شمای ورودی و خروجی. Resources داده فقط‌خواندنی‌اند: فایل، اسکیما، محتوا. Prompt template پیشنهاد پرامپت ازپیش‌نوشته است. خیلی از سرورها فعلاً فقط ابزار دارند. عامل در runtime فهرست را می‌پرسد (`tools/list` و بقیه) و بدون دیپلوی تازه قابلیت جدید را برمی‌دارد.

API، به‌خصوص REST، عمومی است و برای هوش مصنوعی ساخته نشده. کلاینت باید متد و شکل JSON و احراز هویت هر سرویس را بلد باشد. اگر پنج API داشته باشی، اغلب پنج آداپتور می‌خواهی. MCP یک پروتکل برای هر پنج سرور است و کشف پویا دارد؛ API معمولاً ندارد و تغییر endpoint کار توسعه‌دهنده است.

پیچش آخر این است که این دو رقیب نیستند. بسیاری از سرورهای MCP لفاف یک API موجودند. سرور گیت‌هاب ابزار سطح‌بالا آگهی می‌کند و زیرش همان REST گیت‌هاب را صدا می‌زند. MCP لایه دوستانه برای عامل است و API لایه زیرین سیستم. فهرست مثال‌ها از فایل‌سیستم و نقشه و داکر تا اسپاتیفای و داده سازمانی می‌رود.

## نکات کلیدی

- MCP برای عامل طراحی شده؛ REST برای هر کلاینتی. تفاوت در کشف پویا و شمای یکسان است.
- سه اولیه: tool، resource، prompt. الزام نیست هر سرور هر سه را داشته باشد.
- پنج API یعنی پنج قرارداد؛ پنج سرور MCP یعنی همان `tools/call`.
- سرور MCP اغلب API را حذف نمی‌کند؛ ترجمه‌اش می‌کند.
- اگر کاتالوگ ماشینی نباشد، «استاندارد» فقط یک نام روی یکپارچه‌سازی دستی است.

## برش کوتاه

> MCP مثل USB-C است. مهم نیست دیسک را کی ساخته؛ به همان درگاه می‌خورد.

> MCP و API دشمن هم نیستند. لایه‌اند. خیلی وقت‌ها سرور MCP فقط مترجم REST زیر خودش است.
