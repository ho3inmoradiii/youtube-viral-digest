## خلاصه

ایگور (Cloudflare، از سازندگان Angular) و ناتالیا (مدیر محصول در مایکروسافت) در گفت‌وگو با نچیو دان یک ادعا را وسط می‌گذارند: web fragments، برخلاف Module Federation، در مقیاس واقعاً کار می‌کند. بحث سلیقه‌ای نیست. Federation برگ‌های گراف اپ را طوری جدا می‌کند که هنوز ماژول، state و جاوااسکریپت را شریک بمانند. همان اشتراک، در یک نقطه از چرخه عمر، سرنوشت تیم‌ها را به هم گره می‌زند. وعده استقلال تیم، استقلال فناوری، و استقلال تصمیم معماری تا امروز در این مدل‌ها کامل تحویل داده نشده.

رویکرد مخالف را «داکر داخل مرورگر» می‌نامند. زمینه اجرای جاوااسکریپت کاملاً کپسوله است و DOM هم کپسوله است، ولی هنوز یک سند واحد دیده می‌شود. تکنیک‌شان reframing است: کد داخل زمینه iframe اجرا می‌شود، اما برای رسم از DOM خود iframe استفاده نمی‌کنند؛ UI را در سند اصلی می‌گذارند. دردسرهای کلاسیک iframe (دسترس‌پذیری و ظاهر) کم می‌شود چون iframe فقط زندان اسکریپت است نه قاب پیکسل.

ایگور طرف استاندارد پلتفرم است، نه یک فریم‌ورک که خودش نیاز به نگهداری دارد. کد iframe و کش مرورگر را مرورگر نگه می‌دارد. در دمو، کاربر دو اپ را یکی می‌بیند. زیر پوسته، فرگمنت HTML کامل خودش را دارد. تگ‌های script در سند اصلی خنثی شده‌اند تا ایندکس نودهای React برای hydration به‌هم نریزد؛ اگر حذفشان کنی، React ترتیب را گم می‌کند. داده و asset از endpoint خود فرگمنت می‌آید، نه از باندل مشترک میزبان.

## نکات کلیدی

- شکست میکروفرانت معمولاً در نقطه اشتراک ماژول است، نه در روز تقسیم ریپو.
- اگر استقلال تیم وعده اصلی است، اشتراک runtime جاوااسکریپت آن وعده را نقض می‌کند.
- iframe برای اجرا و سند اصلی برای رسم، تلاش برای گرفتن ایزوله‌سازی بدون هزینه UX کلاسیک iframe است.
- استاندارد پلتفرم هزینه نگهداری کمتری از فریم‌ورکی دارد که باید خودت زنده نگه‌ش داری.
- hydration و ترتیب DOM هنوز واقعیت React است؛ حتی معماری «جدا» باید این توهم را حفظ کند.

## برش کوتاه

> Federation سرنوشت تیم‌ها را جایی از چرخه عمر به هم گره می‌زند. ما برعکس می‌رویم: داکر برای مرورگر. جاوااسکریپت داخل iframe است، ولی DOM را آنجا رسم نمی‌کنیم.
