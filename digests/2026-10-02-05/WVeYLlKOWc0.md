## خلاصه

ویدیو رسمی Cursor ده عادت کار با عامل را روی یک سایت شخصی و اتصال Spotify نشان می‌دهد. اول Plan Mode با Shift+Tab: عامل کد را می‌خواند، سؤال دقیق می‌پرسد (چند هنرمند، بازه زمانی)، یک مارک‌داون با فایل‌ها و to-do می‌سازد، و بعد Build همان برنامه را پیاده می‌کند. بار اول خطای مجوز Spotify می‌آید؛ چسباندن همان خطا کافی است تا اصلاح شود. دوم منوی @ و مخصوصاً @branch برای بازبینی تغییرهای همان شاخه، کنار فایل و پوشه و مستند و چت قبلی و خطای لینتر. سوم دستور سفارشی: فایل مارک‌داون داخل `.cursor/commands` مثلاً برای ساخت PR با GitHub CLI، که اگر کامیت نشده اول کامیت کند. چهارم چسباندن تصویر، اینجا برای نزدیک کردن فهرست به Spotify Wrapped، شامل به‌روزرسانی config تصویر راه‌دور. پنجم تکثیر چت برای امتحان مسیر دیگر، با این هشدار که زمینه را کوچک نگه دار. ششم عقربه پنجره زمینه؛ روی Claude حدود ۱۲ درصد در یک کار، و دستور summarize برای فشرده‌سازی که باید عمدی باشد. هفتم نمایش همیشگی مصرف سهمیه به‌جای فقط نزدیک سقف. هشتم میان‌بر باز کردن عامل و عوض کردن مدل. نهم چت تازه برای قابلیت تازه، چون ادامه یک مکالمه تا سقف زمینه کیفیت را خراب می‌کند. دهم checkpoint برای برگرداندن تغییر، با یادآوری که Git هنوز جای ذخیره پایدار است.

دور سریع: صدای اتمام، اعلان سیستمی برای اجازه دستور، نمودار Mermaid از جریان OAuth، و چیدمان عامل با فهرست عامل‌ها، مکالمه وسط، diff راست، و دسترسی به لاگ شبکه و DOM.

## نکات کلیدی

- Plan Mode هزینه حدس غلط را قبل از نوشتن کد می‌گیرد. Build بدون خواندن برنامه همان قطار بدون ترمز است.
- دستور اسلش تیم را از تکرار پرامپت PR خلاص می‌کند؛ خود پرامپت باید قانون کامیت را هم بگوید.
- چت را per قابلیت ببند. زمینه طولانی کیفیت را پایین می‌آورد حتی اگر هنوز جا داشته باشد.
- checkpoint جایگزین Git نیست. برگشت محلی غیر از تاریخچه مشترک است.
- تصویر و @branch زمینه را دقیق می‌کنند؛ «بهترش کن» دقیق نیست.

## برش کوتاه

> اول برنامه را بساز و بخوان، بعد Build. چت را برای قابلیت بعدی نو کن. و اگر checkpoint زدی، یادت باشد Git هنوز جایی است که تغییر واقعاً می‌ماند.
