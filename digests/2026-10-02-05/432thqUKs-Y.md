# Professional Micro-Frontend Shared State Setup

- **عنوان:** Professional Micro-Frontend Shared State Setup
- **لینک:** https://www.youtube.com/watch?v=432thqUKs-Y
- **کانال:** Jack Herrington
- **بازدید:** ۸۱٬۷۸۵
- **موضوع:** Microfrontend shared state routing

## خلاصه

جک هرینگتون، که با زک جکسون کتابی درباره Module Federation نوشته، این‌بار سراغ سخت‌ترین بخش می‌رود: state مشترک. سؤال‌ها ساده نیستند. کدام state manager، چه چیزی بین میکروفرانت‌ها بماند، چه چیزی داخل خودشان بماند، و اصلاً معماری از کجا شروع شود.

دمو یک «گیم‌زون» است با دو بازی: card picker و top number. پوسته بالایی کاربر لاگین‌شده را نشان می‌دهد و بازی‌ها جدا لود می‌شوند. امتیاز باید بین این تکه‌ها زنده بماند. مسیر پیاده‌سازی از مونوریپوی Turborepo شروع می‌شود و هم اشتراک build-time کامپوننت را نشان می‌دهد هم اشتراک runtime. در سمت Webpack، publicPath باید `auto` باشد وگرنه مانیفست remoteEntry مسیر chunkها را غلط حل می‌کند. پلاگین Module Federation نام host، نام فایل مانیفست، و ماژول‌های exposeشده را مشخص می‌کند.

جمع‌بندی ویدیو مهم‌تر از دمو است. خیلی‌ها فکر می‌کنند میکروفرانت‌اند یعنی فقط Module Federation. هرینگتون می‌گوید این برداشت را خودش هم ناخواسته ساخته. وابستگی build-time ساده‌تر است و تا وقتی واقعاً به دیپلوی مستقل runtime نیاز نداری کافی است. انتخاب درست، انتخاب متناسب با اپ است نه مد روز.

## نکات کلیدی

- state مشترک را قبل از انتخاب کتابخانه طراحی کن: چه چیزی واقعاً باید از مرز تیم رد شود.
- publicPath روی `auto` در فدریشن یک جزئیات کوچک با هزینه دیباگ بزرگ است.
- build-time و runtime دو ابزارند، نه دو اردوگاه اخلاقی. اولی مسیر برگشت امن است.
- Module Federation تنها راه میکروفرانت‌اند نیست؛ اگر این تصور را داری، معماری‌ات را دوباره ببین.
- مونوریپو (اینجا Turborepo) اشتراک تایپ و کامپوننت را ارزان‌تر از چند ریپوی کاملاً جدا می‌کند.

## برش کوتاه

> خیلی‌ها فکر می‌کنند Module Federation تنها راه میکروفرانت‌اند است. اگر این برداشت را از من گرفته‌اید، عذر می‌خواهم. وابستگی build-time هم هست. هر کدام را که به اپ تو می‌خورد بردار.
