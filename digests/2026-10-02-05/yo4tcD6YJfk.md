# Micro Frontends - Sharing State between applications

- **عنوان:** Micro Frontends - Sharing State between applications
- **لینک:** https://www.youtube.com/watch?v=yo4tcD6YJfk
- **کانال:** Russell Canfield
- **بازدید:** ۷٬۰۹۳
- **موضوع:** Microfrontend shared state routing

## خلاصه

راسل کنفیلد این قسمت از سری میکروفرانت‌اند را به اشتراک state اختصاص می‌دهد. قبل از کتابخانه، سه سؤال را جدا می‌کند: طراحی کامپوننت چیست، کدام state باید مشترک شود، و چه الگوهایی غیر از «یک استور جهانی» وجود دارد. دمو داخل مونوریپوی Nx است. تصویر هیرو یک میکروفرانت است و ناوبری و صفحه سبد هنوز بیشتر شبیه مونولیت میزبان‌اند. افزودن به سبد با Jotai کار می‌کند: کلیک روی هیرو، دیدن آیتم در سبد، و حذف از سبد.

کتابخانه‌هایی که مرور می‌کند React Context، React Query، Jotai، و یک استور دست‌ساز است. حرفش این است که الگوهای context (ارائه‌دهنده بالا، مصرف‌کننده پایین، قرارداد مشخص) به بقیه کتابخانه‌ها هم منتقل می‌شوند. درد واقعی وقتی شروع می‌شود که اشتراک از مرز ریپو رد شود: تایپ‌های مشترک، نسخه قرارداد، و جزئیات ریزی که داخل یک مونوریپو ارزان‌اند و بیرون از آن ناگهان پروژه جدا می‌شوند.

ویدیو بیشتر کارگاهی است تا گزارش تولید، ولی مرز را درست می‌کشد. state سبد یک قرارداد محصول است، نه یک هوک محلی. اگر هیرو و سبد جدا دیپلوی شوند، همان قرارداد باید نسخه‌گذاری شود.

## نکات کلیدی

- اول تصمیم بگیر چه چیزی محلی است و چه چیزی از مرز UI رد می‌شود. بعد کتابخانه را انتخاب کن.
- Jotai در این دمو برای سبد کافی است؛ Context و React Query الگوهای همسایه‌اند نه رقیب مذهبی.
- مونوریپوی Nx اشتراک تایپ را ساده می‌کند. بیرون از ریپو همان تایپ تبدیل به قرارداد نسخه‌دار می‌شود.
- استور دست‌ساز اغلب از آوردن یک کتابخانه سنگین شفاف‌تر است، اگر سطح اشتراک کوچک باشد.
- سری آموزشی است؛ SLA و تعارض نسخه در تولید این ویدیو پوشش عمیق ندارد.

## برش کوتاه

> اشتراک state فقط انتخاب کتابخانه نیست. طراحی کامپوننت، اینکه چه چیزی مشترک است، و الگوی جایگزین را هم باید جدا کنی. درد واقعی وقتی است که تایپ‌ها از ریپو بیرون می‌روند.
