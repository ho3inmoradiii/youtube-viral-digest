# TypeScript 5.8 Beta: generic return narrowing

- **عنوان:** TypeScript 5.8 Beta Sneak Peek: This New Feature is AWESOME
- **لینک:** https://www.youtube.com/watch?v=lUl6gtytG64
- **کانال:** Typed Rocks
- **بازدید:** ۱۹٬۲۶۳
- **موضوع:** TypeScript JavaScript new features

## خلاصه

ویدیو روی یک قابلیت می‌ایستد که بیش از یک سال در حال توسعه بوده و در بتای ۵٫۸ نشان داده می‌شود. تایپ `User` دو شاخه دارد: `person` با نام و نام خانوادگی، و `company` با نام سازمان. تابع `mockUser` باید با ورودی `"person"` دقیقاً نوع شخص را برگرداند و با `"company"` نوع شرکت را. الگوی طبیعی generic است: `T extends keyof User` و خروجی `User[T]`.

تا ۵٫۷ کامپایلر این باریک‌شدن را داخل بدنه تابع نمی‌فهمد. `return { firstName, lastName }` به `User[T]` نسبت داده نمی‌شود، چون T هنوز هر دو شاخه است. خطای «فاقد return پایانی» هم می‌آید، مگر شاخه default با `undefined` اضافه کنی که خودش نوع را خراب‌تر می‌کند. راه‌حل قبلی overload است: یک امضا برای person، یکی برای company، و پیاده‌سازی با اجتماع هر دو. کار می‌کند و پر از امضای تکراری است.

در ۵٫۸ همان generic بدون overload کامپایل می‌شود. `mockUser("person")` روی hover فقط `firstName` و `lastName` دارد و `mockUser("company")` فقط `name`. گوینده به pull request گیت‌هاب ارجاع می‌دهد که توضیح می‌دهد چرا این باریک‌کردن لازم بوده. سود عملی حذف صفحه overload برای تابع‌هایی است که ورودی‌شان کلید یک اتحاد و خروجی‌شان مقدار همان کلید است.

## نکات کلیدی

- درد واقعی overload اجباری برای برگرداندن `User[T]` بود، نه نبود generic.
- ۵٫۸ باریک‌کردن نوع خروجی را از روی آرگومان generic داخل بدنه تابع می‌فهمد.
- تا وقتی نسخه را بالا نبرده‌ای، overload هنوز راه‌حل درست و خوانا برای همین الگوست.
- این قابلیت کد runtime را عوض نمی‌کند؛ فقط امضای دفاعی را کوتاه می‌کند.
- ویدیو روی بتای در حال توسعه ضبط شده؛ رفتار نهایی را با یادداشت انتشار ۵٫۸ چک کن.

## برش کوتاه

> تا ۵٫۷ باید برای person و company دو overload می‌نوشتی تا نوع برگشتی باریک شود. در ۵٫۸ همان `User[T]` داخل تابع کافی است.
