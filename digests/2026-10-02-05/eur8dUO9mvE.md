## خلاصه

این ویدیو کوتاه همان معماری را با یک رفت‌وبرگشت چت نشان می‌دهد. میزبان می‌تواند اپ چت یا دستیار کد داخل IDE باشد و چند کلاینت داشته باشد. کلاینت با پروتکل MCP به یک یا چند سرور وصل می‌شود. سرور به پایگاه رابطه‌ای یا NoSQL، به API با هر سبکی، یا به فایل و کد محلی وصل است. برای دستیار IDE همین اتصال به کد محلی مهم است.

مثال: کاربر می‌پرسد هوا چطور است یا چند مشتری دارم. میزبان ابزارها را از سرور می‌گیرد، سؤال به‌علاوه فهرست ابزار را به مدل می‌دهد، مدل می‌گوید کدام ابزار، میزبان همان سرور را صدا می‌زند، سرور پایگاه یا API یا کد را اجرا می‌کند، پاسخ برمی‌گردد به مدل، و جواب نهایی به چت. فراخوانی می‌تواند زنجیره‌ای باشد. توصیه پایانی ساده است: اگر عامل می‌سازی پروتکل را ببین، حتی اگر خودت عامل نسازی و مشتری‌ات بسازد.

## نکات کلیدی

- میزبان تجربه کاربر است، سرور درِ داده است، مدل فقط انتخاب‌گر ابزار است.
- نوع پایگاه و سبک API پشت سرور پنهان می‌شود.
- یک سؤال معمولی (تعداد مشتری) بدون ابزار قابل پاسخ نیست؛ مدل تقویم و پایگاه را نمی‌بیند.
- زنجیره چند سرور طبیعی است؛ یک سرور همه‌کاره الزام نیست.
- ویدیو مفهومی است و پیکربندی امنیتی یا احراز هویت را باز نمی‌کند.

## برش کوتاه

> میزبان ابزارها را می‌گیرد، مدل انتخاب می‌کند، سرور پایگاه یا API را اجرا می‌کند، جواب برمی‌گردد به مدل. بدون این حلقه، مدل نمی‌داند چند مشتری داری.
