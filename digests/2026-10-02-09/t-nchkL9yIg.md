# Module Federation با Vite و استیت اتمی

- **عنوان:** Vite and Module Federation Makes Micro-Frontends EASY!
- **لینک:** https://www.youtube.com/watch?v=t-nchkL9yIg
- **کانال:** Jack Herrington
- **بازدید:** 139001
- **موضوع:** Module Federation vs iframe microfrontends

## خلاصه

جک هرینگتون تفاوت اشتراک زمان‌بیلد و زمان‌اجرا را با مثال هدر بین صفحهٔ خانه و صفحهٔ محصول نشان می‌دهد. در مدل کتابخانه‌ای، هر دو اپ هدر را import می‌کنند و برای هر تغییر هدر باید هر دو منتشر شوند. در Module Federation، صفحهٔ خانه هدر را expose می‌کند و صفحهٔ محصول همان را در runtime می‌گیرد؛ نسخهٔ جدید هدر بدون دیپلوی مجدد مصرف‌کننده می‌رسد. این برد برای شرکت‌های بزرگ با چند تیم است که UX یکسان می‌خواهند ولی نمی‌خواهند قفل انتشار مشترک داشته باشند.

دمو با پلاگین federation برای Vite است: اپ remote روی پورت ثابت (strictPort) کامپوننت را expose می‌کند و host از URL ثابت همان remote را می‌کشد. یک اپ می‌تواند هم‌زمان host و remote باشد. مثال دکمهٔ شمارنده نشان می‌دهد تغییر remote، بدون ری‌دیپلوی host، در host دیده می‌شود.

برای استیت مشترک، توصیهٔ او Jotai یا Recoil است نه بزرگ کردن Redux یا Zustand. اتم‌ها اصطکاک دارند: برای به اشتراک گذاشتن دادهٔ جدید باید اتم جدید بسازید. استور واحد را می‌شود بی‌صدا گشاد کرد و هر فیلد اضافه یعنی کوپلینگ بیشتر بین host و میکروفرانت. سطح تماس باید کوچک بماند؛ شناسهٔ کاربر و محتوای سبد، نه کل مدل دامنه. Jotai باید در تنظیم shared به‌صورت singleton بیاید وگرنه هر اپ استور جدا دارد. در ادامه سازگاری با host ساخته‌شده با Webpack 5 را هم نشان می‌دهد: ESM و نسخهٔ React باید هم‌تراز شوند.

## نکات کلیدی

- اشتراک بیلد یعنی هر تغییر کتابخانه، دیپلوی همهٔ مصرف‌کننده‌هاست؛ اشتراک runtime این قفل را برمی‌دارد.
- پورت remote باید ثابت باشد وگرنه host فردا به آدرس مرده وصل است.
- استیت اتمی، گشاد کردن سطح اشتراک را پرهزینه می‌کند؛ استور واحد این اصطکاک را حذف می‌کند.
- هر چه استیت مشترک بزرگ‌تر، کوپلینگ host و ریموت بیشتر.
- Vite و Webpack 5 می‌توانند همان remote را مصرف کنند، به شرط هم‌ترازی ماژول و نسخهٔ React.

## برش کوتاه

> با Redux یا Zustand می‌توانی بی‌دردسر استور را بزرگ کنی. با اتم، برای هر دادهٔ مشترک جدید باید اتم تازه بسازی. آن اصطکاک خوب است، چون دادهٔ بیشتر یعنی کوپلینگ بیشتر.
