# استیت مشترک میکروفرانت: کوچک، تک‌نسخه، و انتخاب بیلد در برابر ران‌تایم

- **عنوان:** Professional Micro-Frontend Shared State Setup
- **لینک:** https://www.youtube.com/watch?v=432thqUKs-Y
- **کانال:** Jack Herrington
- **بازدید:** 81785
- **موضوع:** Microfrontend shared state routing

## خلاصه

ویدیو یک مونوریپو با Turborepo می‌سازد: پوستهٔ اپ، دو بازی به‌عنوان ریموت، و یک زون که هر دو را کنار هم نشان می‌دهد. استیت مشترک با Zustand و persist در localStorage است و عمداً کوچک نگه داشته می‌شود: کاربر لاگین و امتیاز. جک صریح می‌گوید استیت بین‌مایکروفرانت باید حداقل باشد؛ هویت کاربر، شاید JWT، در فروشگاه شاید تعداد سبد. ادغام استورهای Redux را رد می‌کند. هر میکروفرانت می‌تواند استور داخلی خودش را داشته باشد و فقط یک استور سطح‌بالا مشترک بماند. Zustand بیرون از React هم با getState و setState قابل‌استفاده است؛ اگر هیچ Reactی در کار نیست، RxJS را جایگزین منطقی می‌داند.

پوسته فقط هدر و زمینهٔ بصری است. بازی‌ها با Module Federation و پلاگین CRACO روی Webpack 5 expose می‌شوند. نکتهٔ فنی تکراری: publicPath باید auto باشد، React و UI باید singleton باشند وگرنه دو نسخه از هوک استیت در حافظه می‌نشیند و امتیازها از هم جدا می‌مانند. مصرف داینامیک هم به bootstrap ناهمگام نیاز دارد؛ خطای shared module is not available for eager consumption یعنی این قدم جا افتاده.

نیمهٔ دوم ویدیو همان کد را به وابستگی زمان‌بیلد برمی‌گرداند: پکیج games داخل مونوریپو. دیپلوی مستقل از بین می‌رود، ولی باگ «فقط وقتی داخل اپ دیگر embed شد» هم از بین می‌رود و تایپ‌اسکریپت برمی‌گردد. جمع‌بندی او این است که Module Federation تنها راه میکروفرانت نیست. پیش‌فرض منطقی‌تر اغلب اشتراک بیلد است و runtime را فقط وقتی لازم شد روشن کنید.

## نکات کلیدی

- استیت مشترک را به هویت و چند فیلد واقعاً سراسری محدود کنید؛ استورهای Redux را ادغام نکنید.
- singleton روی React و کتابخانهٔ UI، شرط یک نمونهٔ در حافظه از استیت است.
- لود داینامیک ریموت بدون bootstrap ناهمگام، خطای eager consumption می‌دهد.
- runtime sharing دیپلوی مستقل می‌دهد و ریسک باگ فقط در حالت embed را هم می‌دهد.
- پیش‌فرض پیشنهادی: اشتراک زمان‌بیلد در مونوریپو، و فدراسیون فقط در صورت نیاز واقعی.

## برش کوتاه

> خیلی‌ها فکر می‌کنند Module Federation تنها راه میکروفرانت است. نیست. می‌توانی وابستگی زمان‌بیلد داشته باشی یا زمان‌اجرا. ابزار را از روی نیاز محیط انتخاب کن، نه از روی اسم معماری.
