# دو قابلیت TypeScript 5.8: نحوِ پاک‌شدنی و چک بازگشت شرطی

- **لینک:** https://www.youtube.com/watch?v=vcVoyLQMCxU
- **کانال:** Better Stack
- **بازدید:** 29770
- **موضوع:** TypeScript JavaScript new features

## خلاصه

قابلیت اول فلگ `--erasableSyntaxOnly` است. بیشتر تایپ‌اسکریپت فقط در سطح تایپ است و موقع کامپایل پاک می‌شود. enum و namespace و پارامتر shorthand کلاس این‌طور نیستند؛ برایشان جاوااسکریپت زمان‌اجرا ساخته می‌شود و اجرا و باندل سخت‌تر می‌شود. با این فلگ، وجودشان خطا می‌شود. فایدهٔ فوری: Node می‌تواند فایل را فقط با پاک کردن نحو تایپ اجرا کند. گوینده می‌گوید فلگ experimental strip types قبلاً لازم بوده و حالا این رفتار پیش‌فرض شده تا بدون ts-node یا tsx فایل تایپ‌اسکریپت اجرا شود. عدد نسخه‌ای که در گفتار می‌آید مبهم است («۲۰٫۳٫۶»)؛ قبل از تکیه کردن، نسخهٔ Node خودتان را چک کنید. افق بلندتر، نزدیک شدن به تایپ قابل‌اجرا در مرورگر است، اگر نحو غیرقابل‌پاک شدن از مسیر کنار برود.

قابلیت دوم رفع یک سوراخ قدیمی در return typeهای شرطی و indexed access است. تابعی که بر اساس Person یا Website آدرس برمی‌گرداند، حتی بعد از narrow کردن، بیرون از تابع هنوز اجتماع `string | URL` می‌ماند. return type شرطی هم داخل بدنه چک نمی‌شد و خطای «این نوع به نوع شرطی قابل‌انتساب نیست» می‌داد، در حالی که مقدار واقعی درست بود. در 5.8 کامپایلر شاخه را واقعاً چک می‌کند. هنوز شاخهٔ `never` لازم است؛ اگر حذفش کنید narrow شکست می‌خورد. قبل از 5.8 راه‌حل overload بود و هنوز هم هست، ولی حالا خود conditional این کار را می‌کند. همین الگو برای indexed access مثل `Config[K]` هم بسته شده است.

## نکات کلیدی

- enum و namespace و parameter property نحو پاک‌نشدنی‌اند و با erasableSyntaxOnly ممنوع می‌شوند.
- هدف فلگ، اجرای ساده در Node و کمتر کردن جادوی کامپایل است.
- 5.8 بازگشت شرطی و indexed access را داخل بدنه واقعاً چک می‌کند.
- شاخهٔ `never` هنوز برای narrow درست لازم است.
- overload راه‌حل نسخه‌های قبل بود و هنوز معتبر است.

## برش کوتاه

> مشکل این نبود که تابع مقدار غلط برمی‌گرداند. مشکل این بود که تایپ‌اسکریپت اصلاً نوع شرطی بازگشت را تا مقدار واقعی‌اش حل نمی‌کرد. در ۵.۸ آن چک اضافه شده است.
