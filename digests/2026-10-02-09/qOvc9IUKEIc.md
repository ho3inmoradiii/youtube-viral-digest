# چهار قاعده‌ای که مهندس‌های Anthropic با آن Claude را راه می‌برند

- **عنوان:** How Anthropic Engineers ACTUALLY Prompt Claude Code
- **لینک:** https://www.youtube.com/watch?v=qOvc9IUKEIc
- **کانال:** Austin Marchese
- **بازدید:** 571403
- **موضوع:** prompt engineering tricks for coding agents

## خلاصه

ویدیو ادعا می‌کند بیشتر آدم‌ها Claude Code را غلط پرامپت می‌کنند و چهار قاعده را از حرف مهندس‌های Anthropic در AI Code Summit بیرون می‌کشد.

قاعدهٔ اول: به‌جای پرامپت تازه برای هر کار تکراری، skill صدا بزنید. skill پوشه‌ای از دانش رویه‌ای است. لایهٔ مدل زیر همه‌چیز است، لایهٔ ایجنت و پرامپت همان جایی است که اغلب گیر کرده‌ایم، و لایهٔ skill لایهٔ اپلیکیشن است. مثال ساده: به‌جای پرامپت بلند «با لحن من به این ایمیل جواب بده»، یک دستور مشخص مثل پیش‌نویس ایمیل که خود ایمیل را پیوست می‌کند.

قاعدهٔ دوم: skill فقط پرامپت داخل پوشه نیست. سه لایه دارد. توضیح (description) را مدل هر بار می‌بیند تا بفهمد این skill به درد این سوال می‌خورد یا نه؛ اگر مبهم باشد اصلاً انتخابش نمی‌کند. دستورالعمل، دفترچهٔ گام‌هاست. ابزار و اسکریپت و API لایهٔ سوم است و بیشترین اهرم آنجاست. نقل مهندس Anthropic: آدم‌ها پرامپت قشنگ می‌نویسند و بعد ابزاری می‌دهند که پارامترهایش اسم‌شان A و B است؛ مهندسی که بخواهد همان تابع را صدا بزند هم درمانده می‌شود. مثال عملی ویدیو: به‌جای رفت‌وبرگشت برای چک دامنه، اسکریپتی که دامنه را واقعاً وارسی می‌کند داخل skill می‌نشیند و بعد چند ساب‌ایجنت همان را روی هزاران دامنه اجرا می‌کنند.

قاعدهٔ سوم: skillهای کوچک و ترکیب‌پذیر، نه یک skill غول که ایده و اسکریپت و پست را با هم بسازد. skill غول را نمی‌شود محلی دیباگ کرد؛ اصلاح یک گوشه‌اش معلوم نیست کجا را می‌شکند؛ و قابلیت تکراری را باید دوباره ساخت. skill کوچک اگر بهتر شود، هر جریان کاری که صدایش می‌زند بهتر می‌شود. دو پرچم کمترشناخته: `disable-model-invocation` تا فقط انسان بتواند skill خطرناک (ارسال پیام، دیپلوی) را صدا بزند، و مخفی کردن از منوی اسلش تا فقط ایجنت‌ها ببینند.

الگوی ذخیرهٔ اسکریپت: اگر Claude هر جلسه همان اسکریپت پایتون استایل اسلاید را از نو می‌نویسد، اسکریپت را داخل skill بگذارید. کد با ورودی یکسان خروجی یکسان می‌دهد؛ مدل نه. توکن را با اجرای کد عوض می‌کنید.

قاعدهٔ چهارم: پرامپت جمله‌ای با بستن چت می‌میرد؛ skill می‌ماند. هر بار خروجی بد بود بپرسید این اصلاح یک‌باره است یا باید برای همیشه داخل skill برود. هدف خود Anthropic این است که Claude روز سی‌ام از روز اول بهتر باشد، چون هر چیزی که می‌نویسد برای نسخهٔ بعدی خودش قابل‌مصرف بماند.

## نکات کلیدی

- کار تکراری را به skill ببرید، نه به پرامپت تازه‌ای که فردا فراموش می‌شود.
- توضیح مبهم یعنی skill هرگز خودکار انتخاب نمی‌شود.
- ابزار و اسکریپت از متن پرامپت مهم‌ترند؛ پرامپت زیبا با API لخت شکست می‌خورد.
- skill غول‌پیکر را به skillهای تک‌منظوره بشکنید تا اصلاح‌ها مرکب شوند.
- اگر مدل هر بار همان کد را از نو می‌نویسد، آن کد را ذخیره کنید و دوباره اجرا کنید.

## برش کوتاه

> خنده‌دارترین چیزی که می‌بینیم این است که آدم‌ها پرامپت خیلی قشنگ می‌نویسند و بعد ابزاری به مدل می‌دهند که پارامترهایش A و B است. مهندس Anthropic برعکس عمل می‌کند: زور را روی ابزار می‌گذارد.
