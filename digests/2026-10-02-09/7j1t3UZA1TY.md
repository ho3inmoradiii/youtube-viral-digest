# MCP لایهٔ سازگار با مدل است، نه جایگزین API

- **عنوان:** MCP vs API: Simplifying AI Agent Integration with External Data
- **لینک:** https://www.youtube.com/watch?v=7j1t3UZA1TY
- **کانال:** IBM Technology
- **بازدید:** 1236223
- **موضوع:** MCP tools AI agent integrations

## خلاصه

برای اینکه مدل واقعاً به‌درد بخورد باید به داده و ابزار بیرونی وصل شود. تا همین اواخر این کار با API انجام می‌شد. اواخر ۲۰۲۴ آنتروپیک Model Context Protocol را به‌عنوان استاندارد باز معرفی کرد تا روش دادن زمینه به مدل یکسان شود. استعارهٔ ویدیو USB-C است: لپ‌تاپ میزبان است، کابل پروتکل است، مانیتور و دیسک و شارژر سرورهای MCP هستند. مهم نیست سازنده کیست؛ شکل اتصال یکی است.

میزبان چند کلاینت MCP دارد. هر کلاینت یک نشست JSON-RPC 2.0 با سرور باز می‌کند. سرور قابلیت تبلیغ می‌کند: tools برای کارهایی مثل هوا یا ساخت رویداد، resources برای دادهٔ فقط‌خواندنی مثل فایل و اسکیما، و prompt template برای پرامپت‌های پیشنهادی. خیلی از سرورها فعلاً فقط tools دارند. چون کاتالوگ ماشین‌خوان است (`tools/list` و بقیه)، ایجنت موقع اتصال می‌پرسد «چه کار بلدی؟» و بدون دیپلوی مجدد کد کلاینت، قابلیت جدید را برمی‌دارد.

API به‌خصوص REST همچنان قرارداد عمومی وب است: GET و POST و PUT و DELETE، هر سرویس با مسیر و احراز هویت خودش. پنج API یعنی اغلب پنج آداپتور. پنج سرور MCP همان شکل صدا را جواب می‌دهند. تفاوت اصلی هدف است: MCP برای ایجنت و کشف پویا ساخته شده؛ API عمومی است و معمولاً کشف زمان‌اجرا ندارد. اگر endpoint جدید بیاید، توسعه‌دهنده باید کلاینت را به‌روز کند.

نکته‌ای که هیاهو را جمع می‌کند: بسیاری از سرورهای MCP در باطن همان API را صدا می‌زنند. سرور گیت‌هاب ابزار سطح‌بالا مثل لیست مخزن را به درخواست REST ترجمه می‌کند. MCP و API رقیب نیستند؛ لایه‌اند. MCP رابط دوستانه برای مدل است و زیرش می‌تواند API قدیمی بماند. فهرست در حال رشد شامل فایل‌سیستم، نقشه، داکر و اسپاتیفای است، ولی ارزش استاندارد وقتی است که واقعاً چند سیستم را با یک شکل صدا بزنید، نه وقتی یک سرور تنها را به‌خاطر اسمش اضافه می‌کنید.

## نکات کلیدی

- MCP اتصال مدل به ابزار و زمینه را استاندارد می‌کند؛ استعارهٔ درست USB-C است نه «API جدید».
- سه اولیهٔ رایج: tool، resource فقط‌خواندنی، و قالب پرامپت.
- کشف پویای قابلیت، فرق عملی با REST است که معمولاً کاتالوگ زنده ندارد.
- پنج API ناهمگن پنج آداپتور می‌خواهد؛ پنج سرور MCP یک شکل صدا دارند.
- سرور MCP اغلب لفاف یک API موجود است؛ جایگزینی کامل API نیست.

## برش کوتاه

> MCP و API دشمن هم نیستند. لایه‌اند. MCP می‌تواند زیرش همان API را صدا بزند و فقط رویش رابطی بگذارد که ایجنت بفهمد.
