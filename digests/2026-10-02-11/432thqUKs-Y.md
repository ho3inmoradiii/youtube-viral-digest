- **موضوع:** Microfrontend shared state routing

## خلاصه

جک هرینگتون مسئله state در میکروفرانت را با یک دموی عمداً سبک نشان می‌دهد: Game Zone. بالای صفحه یک app shell است با نام کاربر و امتیاز. دو بازی، card picker و top number، هر کدام روی پورت جدا اجرا می‌شوند و از راه میکروفرانت داخل پوسته می‌آیند. نکته عملی همان اول لو می‌رود: localStorage برای هر origin جداست. پورت ۳۰۰۰ و ۳۰۰۱ و ۳۰۰۲ حافظه محلی مشترک ندارند، پس «امتیاز را بریزیم توی localStorage» بین اپ‌ها کار نمی‌کند.

state واقعاً مشترک را پوسته نگه می‌دارد: چه کسی لاگین است و امتیازش چند است. بازی‌ها فقط وقتی لاگین باشی قابل بازی‌اند و با اکشن‌هایی مثل افزودن امتیاز به همان store پوسته حرف می‌زنند. برای ساخت، از توربورپو و مونوریپو با یک کتابخانه UI مشترک و دو اپ شروع می‌کند. برای خود state، Zustand را انتخاب می‌کند چون سبک است، مدل یک‌طرفه شبیه Redux دارد، و برخلاف storeهای قفل‌شده به ری‌اکت می‌شود بیرون از ری‌اکت هم getState و setState و subscribe کرد؛ اگر یکی از تکه‌ها Angular یا JS ساده باشد هنوز به store دسترسی دارد.

بقیه ویدیو سیم‌کشی همین مسیر است: پکیج UI، هوک useAppShell، و بازی‌هایی که به‌جای state جزیره‌ای، امتیاز را به پوسته گزارش می‌دهند. پیام معماری‌اش ساده است. state سراسری را کم و صریح نگه دار (هویت و امتیاز)، state خود بازی را داخل همان میکروفرانت بگذار، و روی حافظه مرورگر به‌ازای هر پورت حساب نکن.

## نکات کلیدی

- localStorage بین originها (اینجا پورت‌های جدا) مشترک نیست؛ برای state بین‌اپ گمراه‌کننده است.
- پوسته فقط چیزی را نگه می‌دارد که چند میکروفرانت واقعاً باید ببینند: نشست و امتیاز.
- بازی‌ها میکروفرانت مستقل‌اند و از طریق API پوسته به state مشترک می‌رسند، نه با import درهم.
- Zustand به‌خاطر حجم کم و قابلیت استفاده خارج از ری‌اکت برای مرز فریم‌ورک مناسب‌تر از store صرفاً ری‌اکتی است.
- مونوریپو (در این ویدیو Turborepo) جای اشتراک کد UI است، نه جای قاطی کردن state همه بازی‌ها.
- اگر مرز state را شل کنی، هر بازی مالک نیمه‌کاره امتیاز می‌شود و پوسته دروغ می‌گوید.

## برش کوتاه

> امتیاز را در localStorage پوسته دیدی و فکر کردی بازی کناری هم همان را می‌بیند. پورت فرق دارد، origin فرق دارد، حافظه فرق دارد. state مشترک باید از پوسته و با قرارداد صریح بیاید، نه از شانس مرورگر.
