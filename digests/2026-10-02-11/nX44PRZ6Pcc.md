## خلاصه

ویدیو کوتاه و صریح است: میکروفرانت روی کاغذ معقول است و در عمل اغلب پیچیدگی اضافه می‌کند. واژه‌هایی مثل دیپلوی مستقل و خودمختاری تیم خریدار زیاد دارند، اما نتیجه رایج چند خط لوله به‌جای یکی، ارکستراسیون مسیریابی به‌جای روت ساده، و incident بین‌تیمی به‌جای باگ محلی است. گوینده مسئله را بیش از هر چیز انسانی می‌داند، نه پلاگین.

بعد ابزارها را از پایین به بالا ردیف می‌کند. iframe قدیمی‌ترین راه است و برای ایزوله‌سازی سخت هنوز کار می‌کند: سندباکس، بدون تصادم وابستگی، مرز روشن. هزینه: استایل زشت و حرف زدن از راه postMessage. Web Components با Shadow DOM نشت CSS را می‌گیرند و custom event ارتباط را ساده می‌کند، بدون بیلد اجباری؛ ولی اشتراک state ساخته‌شده ندارند و تجربه توسعه ضعیف‌تر است. single-spa لایه چسب است: کدام اپ mount شود و کی unmount. چند فریم‌ورک و lazy load وسوسه‌کننده‌اند، تا بفهمی یک سیستم توزیع‌شده داخل مرورگر ساخته‌ای.

Module Federation در Webpack 5 را تنها گزینه‌ای می‌داند که واقعاً وعده را عملی می‌کند: هر اپ هم host است هم remote، manifest جاوااسکریپت در runtime ماژول را پیدا می‌کند، و وابستگی لازم دیرتر لود می‌شود. در پایان به import بومی ESM بین دامنه‌ها و به معماری island در Astro اشاره می‌کند؛ تکه‌های UI که فقط وقتی لازم‌اند بیدار می‌شوند.

## نکات کلیدی

- میکروفرانت اگر مسئله‌اش سازمان نباشد، فقط میکروسرویس را با ابزار ضعیف‌تر داخل مرورگر کپی می‌کند.
- iframe برای ایزوله سخت هنوز معتبر است؛ برای محصول اصلی معمولاً ارتباط و استایل را زشت می‌کند.
- Web Component مرز CSS می‌دهد ولی state مشترک و DX مدرن را نه.
- single-spa هماهنگی mount را حل می‌کند و هم‌زمان incident بین‌تیمی می‌سازد.
- Module Federation با host/remote و manifest، اشتراک runtime را بدون باندل یکجا انجام می‌دهد.
- ESM بومی و islandهای Astro یادآوری می‌کنند که شاید اصلاً به فریم‌ورک میکروفرانت نیاز نباشد.
