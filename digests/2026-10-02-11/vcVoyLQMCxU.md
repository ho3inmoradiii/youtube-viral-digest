## خلاصه

ویدیو دو تغییر تایپ‌اسکریپت ۵.۸ را نشان می‌دهد. اول پرچم `--erasableSyntaxOnly`. بیشتر نحو TS فقط در سطح نوع است و موقع کامپایل پاک می‌شود. enum و namespace و میانبر پارامتر سازنده کلاس این‌طور نیستند؛ برایشان جاوااسکریپت زمان اجرا ساخته می‌شود و اجرا و باندل را پیچیده می‌کند. با این پرچم، وجودشان خطا می‌شود. فایده فوری: خیالت راحت است که Node می‌تواند فایل را فقط با پاک کردن نوع اجرا کند. مسیر Node از فلگ experimental strip types گذشته و در نسخه مورد بحث ویدیو اجرای TS بدون ts-node یا tsx رفتار پیش‌فرض شده. گوینده این را یک قدم به سمت تایپ در مرورگر هم می‌بیند، نه یک قابلیت آماده امروز.

دوم، بررسی مقدار بازگشتی برای نوع شرطی و indexed access. مثال: تابعی که اگر Person باشد address رشته‌ای برمی‌گرداند و اگر Website باشد URL. بدون شرط، نتیجه مصرف‌کننده هنوز اجتماع هر دو نوع می‌ماند. با نوع بازگشتی شرطی، مصرف‌کننده نوع درست را می‌بیند ولی تا قبل از ۵.۸ خود return داخل تابع خطا می‌داد چون TS شاخه را به مقدار نهایی حل نمی‌کرد. در ۵.۸ آن خطا می‌رود. هنوز شاخه `never` لازم است؛ اگر حذفش کنی خطا برمی‌گردد. راه‌حل قدیمی overload بوده و هنوز کار می‌کند، ولی حالا خود conditional چک می‌شود. همین شکاف برای indexed access مثل `Config[T]` (prod رشته، dev بولی) بسته شده است.

## نکات کلیدی

- `erasableSyntaxOnly` enum و namespace و parameter property را ممنوع می‌کند چون کد زمان اجرا می‌سازند.
- هدف عملی، اجرای TS در Node با strip نوع است نه شعار «بی‌نیاز از بیلد برای همه‌چیز».
- نوع در مرورگر در این ویدیو افق است، نه قابلیت ۵.۸.
- TS 5.8 بازگشت شرطی و indexed access را واقعاً با مقدار return تطبیق می‌دهد.
- شاخه `never` در شرط هنوز اجباری است.
- overload قبل از ۵.۸ همان نتیجه مصرف‌کننده را می‌داد؛ تفاوت در صحت داخل بدنه تابع است.

## برش کوتاه

> enum فقط برچسب نوع نیست؛ جاوااسکریپت زنده تولید می‌کند. اگر می‌خواهی Node فایل را با پاک کردن نوع اجرا کند، این نحو باید خطا باشد. و اگر نوع بازگشتی شرطی نوشتی، تا ۵.۸ خود کامپایلر آن شرط را موقع return باور نداشت.
