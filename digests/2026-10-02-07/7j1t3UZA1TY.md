## خلاصه

IBM توضیح می‌دهد مدل برای مفید بودن باید به داده و سرویس بیرون وصل شود و این سال‌ها با API بوده. اواخر ۲۰۲۴ انتروپیک Model Context Protocol را به‌عنوان استاندارد باز معرفی کرد تا رساندن زمینه به مدل شکل ثابت بگیرد. استعارهٔ ویدیو USB-C است: لپ‌تاپ (میزبان MCP) چند کلاینت دارد، هر کلاینت یک نشست JSON-RPC به سرور MCP می‌زند، و مانیتور و دیسک و شارژر مهم نیست سازنده‌شان کیست چون پروتکل یکی است. سرور می‌تواند دیتابیس، ریپوی کد، یا ایمیل باشد.

MCP دو نیاز ایجنت را هدف گرفته: زمینه (سند، رکورد، دانش) و ابزار (جست‌وجو، سرویس، محاسبه). سه primitive: tools یعنی کار قابل صدا زدن با اسم و توضیح و اسکیمای ورودی/خروجی؛ resources یعنی دادهٔ فقط‌خواندنی مثل فایل یا اسکیما؛ prompts یعنی قالب پرامپت پیشنهادی. خیلی از سرورها فعلاً فقط tools دارند. ایجنت موقع اجرا کاتالوگ را می‌پرسد (`tools/list` و بقیه) و بدون دیپلوی مجدد کد، قابلیت جدید را می‌بیند.

API را در مقابل، قرارداد عمومی بین دو سیستم می‌داند، اغلب REST روی HTTP با GET/POST/PUT/DELETE. مدل‌های تجاری خودشان پشت REST هستند. شباهت: هر دو کلاینت-سرورند و جزئیات داخلی را قایم می‌کنند. فرق: MCP برای ایجنت ساخته شده و کشف پویا دارد؛ API عمومی است و با اضافه شدن endpoint معمولاً کلاینت باید دستی به‌روز شود. پنج API یعنی پنج آداپتور؛ پنج سرور MCP یعنی همان شکل صدا زدن. نکته‌ای که ویدیو رویش مکث می‌کند: خیلی از سرورهای MCP در باطن همان API را پیچیده‌اند. سرور گیت‌هاب ابزار سطح بالا می‌دهد و زیرش REST گیت‌هاب را صدا می‌زند. پس رقیب هم نیستند؛ MCP لایهٔ سازگار با ایجنت است و API لایهٔ زیرین.

## نکته‌های کلیدی

- MCP استاندارد اتصال ایجنت به ابزار و زمینه است؛ استعارهٔ کاربردی‌اش پورت مشترک است نه جادو.
- کشف در runtime یعنی ایجنت می‌پرسد چه کارهایی بلدی، به‌جای اینکه شما برای هر endpoint کد تازه بنویسید.
- tools عمل می‌کنند، resources خواندنی‌اند، prompts قالب‌اند؛ هر سرور هر سه را ندارد.
- API را دور نریزید؛ سرور MCP اغلب مترجم همان API است.
- سود عملی برای تیم: یک شکل ادغام به‌جای یک آداپتور برای هر سرویس.
- خطر ضمنی همان دسترسی است: سروری که ابزار دارد، همان کار را واقعاً اجرا می‌کند.

## برش کوتاه

> «پنج API شاید پنج آداپتور بخواهد. پنج سرور MCP به یک شکل جواب می‌دهند: یک‌بار بساز، چند جا وصل کن.»

> «MCP و API رقیب نیستند. لایه‌اند. خیلی از سرورهای MCP زیر پوست همان API را صدا می‌زنند.»
