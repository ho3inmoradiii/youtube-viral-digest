# Micro front-end architecture at Walmart

- **لینک:** https://www.youtube.com/watch?v=BcpDr0CcIxA
- **کانال:** Hasgeek TV
- **بازدید:** 3,404
- **مدت:** حدود ۲۱ دقیقه
- **موضوع:** Micro Frontends production case study

## خلاصه

نادیا، معمار تیم discovery در Walmart Labs بنگلور، توضیح می‌دهد چرا یک ویجت «چک تناسب قطعه با خودرو» را به‌جای قاطی کردن در مونولیت صفحهٔ محصول، به‌صورت فرگمنت مستقل ساختند. زمینه شلوغ است: حدود ۷۰ مهندس بین آمریکا و هند، هم‌زمان حدود ۱۰ ابتکار، صفحات لندینگ با حساسیت بالا به TTFB و First Meaningful Paint، و حدود ۵٬۰۰۰ بازدید صفحه در دقیقه. خود ویجت fitment نزدیک ۱۲۰ فایل و حدود ۶٬۰۰۰ خط کد اضافه می‌کرد؛ ریویو PR در استخر مشترک گاهی دو تا سه روز طول می‌کشید، چون ریویوکننده زمینهٔ محصول را نمی‌شناخت.

تعریف آن‌ها از میکروفرانت کتابی نیست: قطعه‌ای قابل استفادهٔ مجدد که هم روی کلاینت رندر شود هم روی سرور، حدود ۸۰٪ چرخهٔ حیات مستقل داشته باشد، و کارکردش متوسط تا سنگین باشد. رفتار و UX را صفحهٔ میزبان تعیین می‌کند. روی صفحهٔ قطعه، ویجت می‌گوید این برف‌پاک‌کن به این ماشین می‌خورد یا نه؛ همان ویجت روی جست‌وجو کوئری را تنگ می‌کند. ارتباط فقط ناهمگام است، با کتابخانهٔ postal.js، نه با دست‌کاری DOM میزبان.

آن‌ها می‌دانند code splitting و React Loadable همین تکه را دیرتر لود می‌کند، ولی نسخه‌گذاری، اتوماسیون و اجرای مستقل را حل نمی‌کند. فرگمنت اسکلت خودش را در یک پکیج نود دارد، پشت فلگ A/B است، CSS و JS را lazy تزریق می‌کند، API خودش را می‌زند، و باگ‌فیکسش رگرشن کامل صفحهٔ میزبان نمی‌خواهد. کتابخانه‌های مشترک (حدود ۲۰ تا) با Webpack DLL یک مانیفست نسخه دارند تا React دوبار دانلود نشود. هزینهٔ پنهان را هم می‌گوید: فرگمنت یتیم می‌شود، زیرساخت جدا پول می‌خواهد، و اگر قابل پیکربندی نباشد این همه زحمت بی‌معنی است.

## نکته‌های کلیدی

- مقیاس واقعی اینجاست: ۷۰ مهندس، ۱۰ کار موازی، ۵٬۰۰۰ بازدید در دقیقه، نه یک داشبورد داخلی.
- ویجت fitment حدود ۶٬۰۰۰ خط بود؛ هدف کسب‌وکار کاهش مرجوعی قطعهٔ ناسازگار بود، نه نمایش معماری.
- code splitting بار را خرد می‌کند؛ چرخهٔ حیات مستقل (نسخه، تست، ریلیز) را نمی‌دهد.
- میزبان فقط placeholder و چند خط context می‌دهد؛ فرگمنت DOM میزبان را لمس نمی‌کند.
- بودجهٔ پرفورمنس میزبان (TTFB، FMP، چیزی که بالای fold دیده می‌شود) قید سخت است، نه شعار.
- Webpack DLL جلوی چند نسخهٔ React/lodash روی کلاینت را می‌گیرد.
- برد عملی: زمان ریویو کمتر شد و باگ فرگمنت رگرشن کل صفحه نخواست. باخت: یتیم شدن قطعه و هزینهٔ زیرساخت.

## برش کوتاه

> «اگر فرگمنت قابل پیکربندی نباشد، این معماری فقط وزنه‌برداری الکی است. رفتارش باید با صفحهٔ میزبان عوض شود، نه اینکه برای یک use case خاص قفل شود.»

> «React Loadable تکه‌کردن باندل را بلد است. نسخه‌گذاری، اتوماسیون و اجرای مستقل را نه.»
