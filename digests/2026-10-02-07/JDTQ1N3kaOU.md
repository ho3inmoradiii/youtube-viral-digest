## خلاصه

آکاش روی همان ستاپ Module Federation قبلی‌اش نشان می‌دهد چطور یک میکروفرانت (روی localhost:3002) متن صفحهٔ کانتینر را عوض کند. سناریو ساده است: کاربر در ریموت چیزی تایپ می‌کند، submit می‌زند، و عنوان «product listing» در هاست باید همان متن شود.

دو راه را نام می‌برد. اول API: ریموت POST بزند و کانتینر GET کند. چون API دم دست نیست، راه دوم را پیاده می‌کند: Custom Event. در submit، `new CustomEvent("change-text", { detail: { name: text } })` ساخته و روی window دیسپچ می‌شود. هاست در `useEffect` به همان نام گوش می‌دهد، `event.detail.name` را در state می‌گذارد، و عنوان عوض می‌شود. با تایپ «landing page» و submit، متن کانتینر واقعاً عوض می‌شود.

ته ویدیو مهم‌تر از دمو است. می‌گوید MFE رویکرد runtime است چون `remoteEntry.js` موقع اجرا می‌آید، و این وقتی به‌درد می‌خورد که یک تیم کل یک ناحیه (مثلاً صفحهٔ کارت) را مالک باشد. برای چند کامپوننت کوچک روی هوم‌پیج، runtime انتخاب بدی است: چهار نمونه از یک ویجت یعنی چهار بار API، و پرفورمنس سنگین می‌شود. آنجا پکیج npm در build-time درست‌تر است.

## نکته‌های کلیدی

- اشتراک داده بین MFE در این دمو state مشترک جادویی نیست؛ یا API است یا رویداد.
- Custom Event با `detail` سبک‌ترین قرارداد روی همان صفحه است، به شرطی که اسم رویداد قرارداد تیم باشد.
- runtime (remote entry) برای مالکیت یک بخش بزرگ صفحه است، نه برای دکمهٔ تکراری.
- چند نمونه از یک ریموت که هر کدام API خودش را بزند، هزینهٔ پنهان فدراسیون است.
- کامپوننت کوچک را پکیج کنید؛ مرز تیم و روت مستقل را فدره کنید.

## برش کوتاه

> «میکروفرانت برای وقتی است که تیم دوم کل تجربهٔ یک مسیر را تحویل می‌دهد. برای چهار تا کامپوننت کوچک روی هوم، پکیج build-time بهتر است وگرنه چهار بار API می‌زنید.»
