## خلاصه

ویدیو یک عدد را وسط می‌گذارد: ۳۲۲ کیلوبایت، حجم minify و gzip شدهٔ ۱۶ لایبرری رایج UI. ادعا این است که بخش بزرگی از این جاوااسکریپت را می‌شود حذف کرد چون HTML و CSS خودشان جلو آمده‌اند. سال‌ها JS چسب زخم سوراخ‌های پلتفرم بود؛ حالا پلتفرم همان دورزدن‌ها را به یک خط CSS نزدیک کرده. اصل راهنما «کمترین قدرت لازم» است: ضدجاوااسکریپت نیست، یعنی ساده‌ترین ابزار مقاوم برای هر کار.

مثال تولتیپ عینی است. راه قدیمی حدود ۶۰ خط JS برای hover و focus و blur و state. راه تازه حدود ۱۰ خط HTML با Popover API: یک id و атриبیوت `popover`، دکمه با `popovertarget`، بعد CSS. فوکوس، بستن با کلیک بیرون، Escape و دسترس‌پذیری را مرورگر انجام می‌دهد نه میکرومدیریت اسکریپت.

همین الگو را به بقیهٔ UI تعمیم می‌دهد. به‌جای ResizeObserver برای واکنش کامپوننت به عرض خودش، container query. به‌جای GSAP برای افکت اسکرول، scroll-driven animation که کار را از main thread به کامپوزیتور می‌برد. به‌جای روتر برای بعضی گذار صفحات، View Transitions. به‌جای Radix فقط برای مودال، عنصر `dialog`. نمودار اسکرول JS را در برابر CSS می‌گذارد: لیسنر JS هر فریم main thread را می‌کوبد و INP خراب می‌شود؛ نسخهٔ CSS همان کار را بدون رقابت با منطق اپ انجام می‌دهد. LCP هم بهتر می‌شود چون JS کمتری رندر را سد می‌کند و CLS وقتی layout دست موتور خود مرورگر است کمتر می‌جهد.

کیس HTMX را شاهد می‌آورد: ۹۶٪ تعداد وابستگی‌ها کم شده، یعنی آلرت امنیتی کمتر و بیلد ساده‌تر. پیشنهاد عملی: یک تولتیپ یا مودال یا آکاردئون را با popover یا dialog یا details از نو بسازید و ببینید چه چیزی از package.json پاک می‌شود.

## نکته‌های کلیدی

- ۳۲۲ کیلوبایت برای ۱۶ لایبرری UI؛ سؤال این است کدام را پلتفرم همین حالا بلد است.
- Popover API حدود ۶۰ خط JS تولتیپ را به حدود ۱۰ خط HTML نزدیک می‌کند.
- container query کامپوننت را نسبت به فضای خودش واکنش‌گر می‌کند، نه نسبت به viewport.
- scroll-driven animation کار را از main thread برمی‌دارد و مستقیم به INP وصل است.
- `dialog` فوکوس‌ترپ و backdrop و Escape را بدون Radix می‌دهد.
- HTMX با تکیه بر پلتفرم ۹۶٪ وابستگی را کم کرده؛ بردش نگه‌داری است، نه فقط حجم.

## برش کوتاه

> «هدف حذف جاوااسکریپت نیست. هدف این است کاری را که مرورگر برایش ساخته شده به خودش بسپاریم.»

> «INP بهتر می‌شود چون main thread آزاد است به کلیک جواب بدهد، نه اینکه هر فریم انیمیشن اسکرول را حساب کند.»
