## خلاصه

ویدیو دو قابلیت TypeScript 5.8 را نشان می‌دهد، حدود یک ماه مانده به انتشار آن نسخه. هر دو را می‌شود روی بیلد nightly که آن موقع ۵.۸ است امتحان کرد. یکی را حذف چند قابلیت می‌داند و دیگری را رفع یک باگ قدیمی در بررسی نوع برگشتی.

اول پرچم erasable syntax only است. بیشتر TypeScript فقط در سطح نوع است و موقع کامپایل پاک می‌شود و جاوااسکریپت می‌ماند. enum و namespace و شکل کوتاه پارامتر سازندهٔ کلاس این‌طور نیستند؛ برایشان کد زمان اجرا ساخته می‌شود و اجرا و باندل سخت‌تر می‌شود. با این پرچم آن قابلیت‌ها حذف می‌شوند و اگر در کد باشند TypeScript خطا می‌دهد. فایدهٔ عملی این است که مطمئن می‌شوید Node می‌تواند فایل TypeScript را بدون پیکربندی اضافه اجرا کند. قبلاً پرچم experimental strip types همین پاک‌کردن نوع را ممکن می‌کرد؛ گوینده می‌گوید این رفتار حالا پیش‌فرض Node است و دیگر به ts-node یا tsx نیاز نیست. در افق بلندتر هم آن را یک قدم به سمت پشتیبانی TypeScript در مرورگر می‌داند.

دوم، بررسی عبارت return برای نوع شرطی و نوع دسترسی با اندیس است. مثال اول دو نوع Person و Website است؛ هر دو name دارند، Person یک address از جنس string دارد و Website یک URL. تابعی که یکی از این دو شیء را می‌گیرد و آدرس را برمی‌گرداند، اگر نوع برگشتی را string | URL بگذارید، حتی بعد از تشخیص نوع ورودی، نتیجه هنوز string | URL می‌ماند. با نوع برگشتی شرطی (اگر Person باشد string، اگر Website باشد URL، وگرنه never) موقع استفاده نوع درست درمی‌آید، ولی روی خود return خطا می‌ماند: URL به آن نوع شرطی قابل انتساب نیست، چون TypeScript شرط را تا مقدار واقعی چک نمی‌کرد. در nightly نسخهٔ ۵.۸ این خطا می‌رود و مقدارهای برگشتی درست می‌مانند.

ساده‌سازی شرط به «اگر Person نبود پس URL» هنوز خطا می‌دهد. گوینده می‌گوید باریک کردن نوع برگشتی شرطی لازم دارد پیشانی شرط never باشد و باید همان شاخه را صریح نوشت. قبل از ۵.۸ هم با overload می‌شد به همان نتیجه رسید: امضای جدا برای Person با خروجی string و برای Website با خروجی URL، در حالی که پیاده‌سازی هنوز string | URL را اعلام می‌کند. بخش اندیس همین مشکل را روی یک interface به نام Config نشان می‌دهد: prod از نوع string و dev از نوع boolean. تابع با T extends keyof Config باید Config[T] برگرداند. اگر prod باشد URL رشته‌ای برمی‌گردد و اگر dev باشد true. مصرف‌کننده نوع درست string یا boolean را می‌بیند، ولی return هنوز خطا دارد چون نوع اندیس واقعاً باز نمی‌شود. در ۵.۸ این بررسی انجام می‌شود و خطا می‌رود. اینجا هم overload قبلاً راه‌حل بود.

## نکات کلیدی

- پرچم erasable syntax only استفاده از enum، namespace و پارامتر کوتاه کلاس را خطا می‌کند چون کد زمان اجرا تولید می‌کنند.
- هدف عملی، اجرای TypeScript در Node فقط با پاک کردن نوع است؛ experimental strip types قبلاً این کار را می‌کرد و حالا طبق ویدیو پیش‌فرض شده و ts-node و tsx لازم نیست.
- نوع برگشتی شرطی Person/Website تا ۵.۸ روی return چک نمی‌شد، حتی وقتی در محل فراخوانی نوع درست دیده می‌شد.
- در ۵.۸ همان return بدون خطا می‌ماند، به شرط اینکه شاخهٔ never هنوز در شرط باشد.
- حذف never و گفتن «هر چه Person نیست URL است» دوباره خطای انتساب را برمی‌گرداند.
- دسترسی اندیسی Config[T] برای prod: string و dev: boolean هم در ۵.۸ واقعاً چک می‌شود.
- هر دو مورد را قبل از ۵.۸ می‌شد با overload پوشش داد؛ بیلد nightly همان موقع ۵.۸ است.

## برش‌های مهم

- enum و namespace و میانبر پارامتر کلاس پاک‌شدنی نیستند، چون به‌جای نوع خالص برایشان جاوااسکریپت زمان اجرا ساخته می‌شود.
- TypeScript نوع شرطی برگشتی را تا مقدار string یا URL که از شرط درمی‌آید چک نمی‌کرد.
- باریک کردن این نوع برگشتی لازم دارد اولین شاخهٔ شرط never باشد و باید آن را صریح بنویسید.
