## خلاصه

آکاش این ویدیو را ادامهٔ پروژه‌ای می‌داند که قبلاً با Module Federation ساخته. دو پوشه دارد، mf1 و mf2. یکی از این میکروفرانت‌اندها داخل اپ کانتینر نشسته و روی localhost:3002 میزبانی شده. صفحهٔ میزبان یک متن ساده به اسم product listing دارد و اپ مهمان یک کارت با یک دکمه است.

سناریوی دمو این است که از داخل میکروفرانت‌اند روی دکمه‌ای با عنوان تغییر متن کانتینر کلیک شود، یک input و دکمهٔ submit باز شود، کاربر چیزی مثل landing page بنویسد و با submit، متن product listing در اپ اصلی عوض شود. باز و بسته شدن این فرم را با کد سادهٔ React نوشته و می‌گوید همان کد را به گیت‌هاب هم می‌فرستد.

دو راه برای رد و بدل داده بین MFEها مطرح می‌کند. راه اول API است: اپ مهمان با یک POST دادهٔ فرم را بفرستد و کانتینر با یک GET همان را بگیرد و رندر کند. این راه را پیاده نمی‌کند، چون API دم دستش نیست. راه دوم، که می‌گوید پرکاربرد هم هست، رویداد سفارشی است و همان را کد می‌زند.

در handleSubmit یک CustomEvent می‌سازد. اسم رویداد را change text می‌گذارد و در detail یک آبجکت می‌فرستد که فیلد name همان متن داخل input است. بعد رویداد را dispatch می‌کند. سمت میزبان با useState متن پیش‌فرض را «product listing page» می‌گذارد. داخل useEffect به همان نام change text گوش می‌دهد، اول event.detail.name را در کنسول لاگ می‌کند تا مطمئن شود مقدار رسیده، و بعد همان را در state می‌نشاند. آرایهٔ وابستگی effect را خالی می‌گذارد. در دمو عبارتی نزدیک به landing page تایپ می‌کند، submit می‌زند و عنوان میزبان عوض می‌شود. بار دوم هم همان مسیر دوباره کار می‌کند.

آخر ویدیو از اشتراک کد بین تیم‌ها حرف می‌زند و دو رویکرد build-time و runtime را جدا می‌کند. میکروفرانت‌اند را runtime می‌داند، چون remoteEntry.js در زمان اجرا در دسترس است؛ اینجا از همان localhost:3002. می‌گوید اگر فروشگاه اینترنتی داشته باشی و یک تیم صفحهٔ اصلی را بسازد و تیم دیگر کل قابلیت card را برای یک مسیر جدا تحویل بدهد، MFE مناسب است. برای کامپوننت‌های ریز روی همان صفحهٔ اصلی مناسب نیست و باید سراغ پکیج npm و رویکرد زمان بیلد رفت. دلیلش کارایی است: اگر آن کامپوننت یک بار API بزند و چهار نمونه از آن روی صفحه باشد، چهار درخواست می‌رود و کار سنگین می‌شود.

## نکات کلیدی

- ستاپ از قبل با Module Federation است: میزبان و یک میکروفرانت‌اند روی localhost:3002، با متن product listing در یک طرف و کارت و دکمه در طرف دیگر.
- هدف دمو این است که متن تایپ‌شده در اپ مهمان، بعد از submit، عنوان اپ کانتینر را عوض کند.
- راه API یعنی POST از مهمان و GET در کانتینر؛ این راه را به‌خاطر نداشتن API پیاده نمی‌کند.
- راه رویداد سفارشی را کد می‌زند: CustomEvent با نام change text و payload داخل detail.name، سپس dispatch.
- میزبان با useState از «product listing page» شروع می‌کند، در useEffect به change text گوش می‌دهد و متن را جایگزین می‌کند؛ در دمو این کار دو بار پشت سر هم جواب می‌دهد.
- MFE را رویکرد runtime می‌داند چون remoteEntry.js موقع اجرا لود می‌شود، مناسب وقتی یک تیم کل یک بخش مثل card را روی مسیر خودش تحویل می‌دهد.
- برای کامپوننت‌های کوچک همان صفحه، پکیج زمان بیلد را بهتر می‌داند، چون چند نمونه از یک قطعهٔ APIمحور به چند درخواست جدا تبدیل می‌شود.

## برش‌های مهم

- از میکروفرانت‌اند یک رویداد change text با متن اینپوت پرتاب می‌شود و میزبان همان را جای عنوان خودش می‌گذارد.
- راه API را کنار گذاشت، چون API آماده نداشت، و سراغ رویداد سفارشی رفت.
- برای تکه‌های کوچک صفحه MFE مناسب نیست؛ چهار نمونه از یک کامپوننت یعنی چهار بار صدا زدن API.
