## خلاصه

ویدیوی IBM می‌گوید مدل زبانی برای مفید بودن باید با داده و سرویس و ابزار بیرونی حرف بزند و تا همین اواخر این کار معمولاً با API بوده است. در اواخر ۲۰۲۴ انتروپیک پروتکل باز Model Context Protocol یا MCP را معرفی کرد تا نحوهٔ دادن زمینه به LLM استاندارد شود. استعارهٔ اصلی USB-C است: لپ‌تاپ چند درگاه دارد و مانیتور و دیسک و شارژر، فارغ از سازنده، با یک استاندارد وصل می‌شوند. در معماری MCP یک میزبان چند کلاینت را اجرا می‌کند. هر کلاینت یک نشست JSON-RPC 2.0 با پروتکل MCP به سرور بیرونی باز می‌کند. سرورها قابلیت را عرضه می‌کنند؛ مثلاً یکی پایگاه داده، یکی مخزن کد، یکی ایمیل. لپ‌تاپ شبیه میزبان است، اتصال USB-C شبیه خود پروتکل، و دستگاه‌های جانبی شبیه سرور MCP.

برای اپلیکیشن LLM، به‌خصوص ایجنت، دو نیاز را پوشش می‌دهد: زمینه به‌شکل دادهٔ زمینه‌ای، و امکان استفاده از ابزار. زمینه یعنی سند، مدخل پایگاه دانش و رکورد پایگاه. ابزار یعنی کارهایی مثل جست‌وجوی وب، صدا زدن سرویس بیرونی یا محاسبه. سرور این‌ها را با primitiveها اعلام می‌کند. ابزار کنش گسسته است؛ سرویس هوا ممکن است get weather بدهد و تقویم create event. سرور نام، توضیح و طرح ورودی و خروجی را در فهرست قابلیت‌ها اعلام می‌کند و وقتی مدل از راه کلاینت ابزار را صدا بزند، تابع زیرین را اجرا می‌کند. منبع دادهٔ فقط‌خواندنی است که کلاینت در لحظه می‌گیرد: فایل متنی، شمای پایگاه، محتوای فایل. قالب پرامپت، پرامپت پیشنهادی از پیش تعریف‌شده است. هر سرور مجبور نیست هر سه را داشته باشد و خیلی‌ها فعلاً فقط روی ابزار تمرکز دارند. ایجنت در زمان اجرا می‌پرسد چه چیزی موجود است و همان را یک‌شکل صدا می‌زند. چون کاتالوگ ماشین‌خوان است، با tools/list و resources/list و prompts/list، قابلیت تازه بدون استقرار مجدد کد کشف می‌شود.

API را مجموعهٔ قواعد درخواست اطلاعات یا سرویس از سیستم دیگر تعریف می‌کند تا همه‌چیز از صفر ساخته نشود؛ مثال، API پرداخت در سایت فروش. کلاینت جزئیات داخلی سرور را نمی‌داند و فقط قالب درخواست و پاسخ را بلد است. سبک غالب REST روی HTTP است: GET برای خواندن، POST برای ساختن، PUT برای به‌روزرسانی، DELETE برای حذف. مثال کتابخانه: GET روی `/books/123` جزئیات کتاب را می‌گیرد و POST روی `/loans` امانت را می‌سازد. پاسخ اغلب JSON است. خیلی از مدل‌های تجاری هم روی REST هستند: پرامپت JSON می‌رود و تکمیل JSON برمی‌گردد. ایجنت هم ممکن است با REST جست‌وجو کند یا سرویس داخلی شرکت را صدا بزند.

شباهت: هر دو کلاینت‌سرور هستند، هر دو جزئیات پیاده‌سازی را قایم می‌کنند و اتصال را ساده می‌کنند. تفاوت: MCP مخصوص وصل کردن اپ LLM به داده و ابزار ساخته شده و فرض‌هایی دارد که به کار ایجنت می‌آید؛ API عمومی است و از اول برای هوش مصنوعی طراحی نشده. مزیت مهم MCP کشف پویاست. کلاینت می‌پرسد چه کار می‌توانی بکنی و فهرست تابع و داده را می‌گیرد و خودش را وفق می‌دهد. REST معمولاً چنین کشفی در زمان اجرا ندارد و با endpoint تازه، توسعه‌دهنده باید کلاینت را به‌روز کند. ایجنت MCP هر بار وصل شدن می‌تواند فهرست تازه را بگیرد. استاندارد رابط هم فرق دارد: هر سرور MCP همان پروتکل و همان الگو را حرف می‌زند، ولی هر API مسیر و پارامتر و احراز هویت مخصوص خودش را دارد. پنج REST ممکن است پنج آداپتور بخواهد؛ پنج سرور MCP به همان شکل صدا جواب می‌دهند.

نکتهٔ پایانی این است که خیلی از سرورهای MCP زیر پوست از API سنتی استفاده می‌کنند و در واقع لفافه‌اند. مثال، سرور MCP گیت‌هاب ابزار سطح‌بالایی مثل repository/list را به‌عنوان primitive عرضه می‌کند و داخلش هر صدا را به درخواست REST گیت‌هاب ترجمه می‌کند. پس این دو رقیب نیستند و لایه‌اند. MCP می‌تواند API را زیر خودش داشته باشد و رویش رابط سازگارتر با هوش مصنوعی بدهد. از سرورهای موجود برای فایل‌سیستم، گوگل‌مپ، داکر، اسپاتیفای و منابع سازمانی رو به رشد اسم می‌برد.

## نکات کلیدی

- MCP اواخر ۲۰۲۴ توسط انتروپیک به‌عنوان استاندارد باز معرفی شده و اتصال اپ هوش مصنوعی به داده و ابزار را مثل USB-C یک‌شکل می‌کند.
- میزبان کلاینت‌ها را اجرا می‌کند. هر کلاینت با JSON-RPC 2.0 به سرور MCP وصل می‌شود.
- سه primitive: ابزار برای کنش، منبع فقط‌خواندنی، و قالب پرامپت. خیلی از سرورها فعلاً فقط ابزار دارند.
- کشف با tools/list و resources/list و prompts/list است و قابلیت جدید بدون دیپلوی مجدد کلاینت دیده می‌شود.
- REST روی HTTP با GET و POST و PUT و DELETE کار می‌کند و معمولاً کشف هم‌تراز در زمان اجرا ندارد؛ هر سرویس قرارداد جدا دارد.
- پنج API ممکن است پنج آداپتور بخواهد. پنج سرور MCP همان صداها را می‌فهمند.
- MCP اغلب لفاف API موجود است، مثل ترجمهٔ repository/list به REST گیت‌هاب. این دو لایهٔ یک پشته‌اند، نه جایگزین هم.

## برش‌های مهم

- MCP مثل درگاه USB-C است: ابزارهای مختلف با یک استاندارد به اپ هوش مصنوعی وصل می‌شوند، فارغ از اینکه چه کسی ساخته.
- کلاینت MCP می‌تواند بپرسد چه کار بلدی و فهرست قابلیت را بگیرد؛ در REST معمولی این کشف زمان اجرا نیست.
- خیلی از سرورهای MCP در عمل لفاف یک API سنتی‌اند و این دو رقیب هم نیستند، لایهٔ روی هم‌اند.
