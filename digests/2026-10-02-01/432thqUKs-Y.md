# Professional Micro-Frontend Shared State Setup

- **عنوان:** Professional Micro-Frontend Shared State Setup
- **url:** https://www.youtube.com/watch?v=432thqUKs-Y
- **کانال:** Jack Herrington
- **بازدید:** 81783
- **موضوع:** Microfrontend shared state routing
- **زیرنویس:** auto، en

## خلاصه

جک هرینگتون، که خودش را مهندس فول‌استک ارشد معرفی می‌کند و می‌گوید با زک جکسون دربارهٔ Module Federation کتاب نوشته، یک پوستهٔ بازی و دو بازی را هم با اشتراک زمان اجرا و هم با اشتراک زمان بیلد می‌سازد. کانال را هم تازه به ۵۰ هزار مشترک رسانده، چیزی که امید داشته تا پایان ۲۰۲۲ برسد و در آوریل همان سال شده است. سه سطح جدا است: کارت‌چین، بازی عدد بالا، و Game Zone که هر دو را کنار هم می‌آورد. در کارت‌چین پنج کارت است و امتیاز از صفر شروع می‌شود؛ کلیک می‌تواند امتیاز را یکی کم کند یا ده تا زیاد. در عدد بالا با Play عدد بالا می‌رود و اگر تا تمام شدن زمان Take نزنید یک امتیاز کم می‌شود و اگر بزنید همان مقدار، مثلاً چهار، اضافه می‌شود. هدر پوسته نام منطقهٔ بازی، کاربر واردشده و امتیاز جاری را نشان می‌دهد. بدون ورود بازی بسته است. هر اپ پورت خودش را دارد: کارت‌چین ۳۰۰۰، Game Zone ۳۰۰۱ و عدد بالا ۳۰۰۲. چون پورت‌ها جدا هستند localStorage هر کدام جدا است. پوسته فقط هویت کاربر و امتیاز را نگه می‌دارد و دو بازی به‌صورت میکروفرانت‌اند داخل Game Zone جمع می‌شوند. روایت محصولی‌اش این است که هر بازی می‌تواند مقدمهٔ دنیای جداگانه‌ای از چالش‌ها باشد.

پایه Turborepo است که می‌گوید حدود یک سال قبل از فیس‌بوک آمده و استارترش کتابخانهٔ UI ری‌اکت به‌علاوهٔ دو اپ docs و web دارد. با pnpm و create-turbo پوشهٔ gamezone را می‌سازد. بستهٔ ui دکمهٔ نمونه را با وابستگی workspace به اپ‌ها می‌دهد، پس داخل مونوریپو تغییر بدون بیلد و استقرار جدا دیده می‌شود. برای state، Zustand را انتخاب می‌کند چون سبک است، مدل یک‌طرفه شبیه Redux دارد و با getState و setState و subscribe بیرون از ری‌اکت هم قابل استفاده است؛ اگر در اکوسیستم اصلاً ری‌اکت نباشد RxJS را محتمل‌تر می‌داند، چون Zustand از راه هوک‌ها به ری‌اکت گرهٔ ضمنی دارد. UI با Mantine است. هوک useAppShell کاربر را رشته یا null و امتیاز را عدد نگه می‌دارد، با setUser و addToScore. خود create را حدود ۹۱۶ بایت می‌گوید. تأکید معماری این است که state مشترک بین میکروفرانت‌اندها تا حد ممکن کوچک بماند: هویت کاربر، شاید JWT برای API، در فروشگاه تعداد یا اقلام سبد، و این‌جا فقط امتیاز بازی. بیشتر از این نه. سؤال‌های ادغام فروشگاه‌های Redux را رد می‌کند؛ Redux DevTools چند فروشگاه روی یک صفحه را ممکن می‌کند، پس هر میکروفرانت‌اند فروشگاه خودش را دارد و فقط یک فروشگاه سطح بالا برای هویت و امتیاز است. میان‌افزار persist با نام app shell وضعیت را در localStorage می‌گذارد تا رفرش خروج نکند.

پوسته هدر آبی، عنوان، و دکمهٔ ورود است که کاربر را jack می‌گذارد و بعد نام و امتیاز و خروج را نشان می‌دهد. بستهٔ ui اولیه برای مصرف در اپ‌های تازه بیش از حد ساده است، پس با tsup خروجی را watch می‌کند، CommonJS و یک خروجی ماژول index.mjs می‌سازد و React را external می‌گذارد. در حالت dev رفرش فوری مونوریپو را نشان می‌دهد، هرچند در استقرار واقعی این وابستگی‌ها زمان بیلد هستند. بازی کارت با Mantine و shuffle از lodash است. کارت‌ها ۱۰ و ۵ و ۲ مثبت و ۱ و ۲ منفی‌اند و خودش می‌گوید برای کازینو بد است چون برد بیشتر از باخت است. اگر کاربر null باشد بازی رندر نمی‌شود. کلیک، مقدار کارت را با addToScore به همان useAppShell می‌دهد. ESLint در این چیدمان خطا می‌دهد و پلاگینش را فقط در dev خاموش می‌کند.

برای دادن کارت‌چین به Game Zone در زمان اجرا، CRACO کانفیگ Webpack اپ Create React App را عوض می‌کند. publicPath باید auto باشد وگرنه مانیفست remoteEntry به باندل‌ها درست اشاره نمی‌کند. ModuleFederationPlugin داخل Webpack 5 نام cardPicker، فایل remoteEntry و expose مسیر کارت را ثبت می‌کند. همهٔ وابستگی‌های غیر dev در shared می‌روند و ui و react و react-dom تک‌نمونه (singleton) هستند. خطای Shared module is not available for eager consumption یعنی Webpack برای ماژول پویا جا می‌خواهد؛ index فقط bootloader را ایمپورت می‌کند و bootloader اپ را ناهمگام بار می‌زند. بعد remoteEntry روی پورت ۳۰۰۰ کارت‌چین را فهرست می‌کند. Game Zone روی ۳۰۰۱ همان ریموت را از localhost:3000/remoteEntry.js مصرف می‌کند. چون Module Federation فایل JS می‌دهد نه تایپ، مصرف‌کننده را jsx می‌کند و می‌گوید تایپ جداگانه موضوع ویدیوی بعدی است. با singleton بودن ui فقط یک useAppShell در حافظه می‌ماند، پس کلیک کارت امتیاز هدر را از ۱۶ به ۲۱ برای jack جلو می‌برد. اگر تکه‌ای Angular یا Vue یا جاوااسکریپت ساده باشد هنوز می‌تواند با getState و setState به همان پوسته حرف بزند.

بازی عدد بالا هم ریموت است، روی پورت ۳۰۰۲. عدد هدف بین ۲ و ۱۲ است و useEffect هر ۵۰۰ میلی‌ثانیه مقدار جاری را یکی زیاد می‌کند؛ اگر از سقف بگذرد یک امتیاز کم می‌شود و بازی ریست می‌شود. دکمهٔ دوم را snag it می‌نامد. فراموش کردن bootstrap همان خطای shared module را برمی‌گرداند. Game Zone هر دو ریموت را پویا لود می‌کند. ارزشش برای سه تیم جدا این است که تغییر عدد بالا در مدل زمان بیلد هم اپ خودش را می‌خواهد هم Game Zone را، ولی این‌جا فقط استقرار مجدد همان ریموت کافی است چون Game Zone در مرورگر همان لحظه کامپوننت را می‌گیرد. ریسک هم همان‌قدر بزرگ است: باگ ممکن است فقط وقتی دیده شود که بازی داخل اپ دیگر نشسته. Error boundary یک راه مهار است؛ راه دیگر پرهیز از ریسک زمان اجرا با وابستگی زمان بیلد است.

روی برنچ build-time-deps بستهٔ packages/games را از روی زیرساخت ui کپی می‌کند، کد هر دو بازی را به آن منتقل می‌کند، lodash و وابستگی workspace به ui را آن‌جا می‌گذارد و Zustand را از این بسته برمی‌دارد چون مال پوسته است. اپ‌ها به‌جای CRACO و remoteEntry، کارت و عدد بالا را از بستهٔ games می‌گیرند و فایل مصرف‌کننده دوباره tsx می‌شود چون تایپ هم مشترک است. هر دو حالت بالا می‌آیند. جمع‌بندی‌اش این است که جواب درست و غلط مطلق نیست. Module Federation را آسان نشان داد ولی ریسک ذاتی دارد و پیش‌فرض خودش اشتراک زمان بیلد با Turborepo است و فقط وقتی لازم شد سراغ وابستگی زمان اجرا می‌رود. می‌گوید خیلی‌ها خیال می‌کنند Module Federation تنها راه میکروفرانت‌اند است و اگر این برداشت از ویدیوهای قبلی آمده عذر می‌خواهد؛ هر دو راه معتبرند و کد روی گیت‌هاب است.

## نکات کلیدی

- پوسته فقط کاربر و امتیاز را در Zustand پایدار روی localStorage نگه می‌دارد؛ هر بازی فروشگاه بزرگ مشترک نمی‌گیرد.
- پورت‌های ۳۰۰۰ و ۳۰۰۱ و ۳۰۰۲ یعنی localStorage هر اپ جدا است؛ امتیاز مشترک داخل Game Zone از تک‌نمونه بودن ماژول ui در حافظه می‌آید نه از storage مشترک.
- ادغام فروشگاه‌های Redux را رد می‌کند: چند فروشگاه روی صفحه ممکن است و فقط دادهٔ واقعاً سراسری باید یکی باشد.
- CRACO به‌علاوهٔ publicPath برابر auto و bootstrap ناهمگام، خطای eager consumption را در Create React App برطرف می‌کند.
- singleton برای ui و react و react-dom لازم است وگرنه هر تکه نسخهٔ خودش از هوک پوسته را دارد.
- استقرار مستقل زمان اجرا یعنی باگ ریموت می‌تواند فقط داخل میزبان ظاهر شود؛ Error boundary یکی از مهارهاست.
- شاخهٔ زمان بیلد همان بازی‌ها را بستهٔ workspace می‌کند، CRACO حذف می‌شود و TypeScript برمی‌گردد.
- پیش‌فرض پیشنهادی او Turborepo و وابستگی زمان بیلد است و Module Federation را برای وقتی می‌گذارد که اشتراک زمان اجرا واقعاً لازم باشد.

## برش‌های مهم

- state مشترک را کوچک نگه دارید: هویت کاربر، شاید JWT، و چیزی مثل امتیاز یا تعداد سبد؛ نه بیشتر.
- اگر ui تک‌نمونه نباشد، هر میکروفرانت‌اند نسخهٔ جدا از useAppShell را در حافظه دارد و امتیاز هدر با کلیک بازی یکی نمی‌شود.
- در زمان بیلد تغییر بازی هم خودش را دوباره مستقر می‌کند هم Game Zone را؛ در زمان اجرا فقط همان ریموت کافی است.
- Module Federation تنها راه میکروفرانت‌اند نیست؛ وابستگی زمان بیلد هم همان کار را با ریسک کمتر می‌کند.
