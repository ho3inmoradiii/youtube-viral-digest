## خلاصه

کایل از Web Dev Simplified چهار تغییر TypeScript 5.5 را کنار ویرایشگر ۵.۴ مقایسه می‌کند. اولی همان چیزی است که می‌گوید سال‌ها منتظرش بوده: filter روی آرایه نوع را واقعاً تنگ نمی‌کرد. آرایه‌ای از number و null بعد از حذف nullها در ۵.۴ هنوز number | null می‌ماند و افزودن ۲ خطا می‌دهد، چون TypeScript هنوز احتمال null را می‌بیند. در ۵.۵ همان آرایه number[] است و خطا می‌رود. این فقط به مقایسهٔ ساده با null محدود نیست. اگر آرایه string | number | null باشد و filter با تابعی انجام شود که نوع مقدار را چک می‌کند و فقط number را نگه می‌دارد، سمت ۵.۵ نتیجه را number[] می‌بیند و ۵.۴ این باریک‌سازی را بلد نیست.

دومی هم استنباط نوع است، این بار برای خواندن مقدار از روی کلید. شیء از نوع Record با کلید string و مقدار number | boolean است. تابع کلید را می‌گیرد و اگر مقدار عدد باشد یکی به آن اضافه می‌کند و چاپ می‌کند. در ۵.۴ بعد از همان if هنوز معلوم نیست مقدار number است یا boolean. راه‌حل قدیمی یک متغیر میانی بود تا نوع باریک شود، یعنی برای رفع خطای TypeScript کد جاوااسکریپت اضافه می‌شد. در ۵.۵ خود عبارت شیء و کلید بعد از بررسی، number استنباط می‌شود و افزودن یک بی‌خطا است.

سومی بررسی خود عبارت منظم است و قابلیت تازه‌تری نسبت به دو بهبود استنباط است. در ۵.۴ TypeScript با دیدن regex آن را نادیده می‌گرفت و خطایی نبود. در ۵.۵ به داخل الگو نگاه می‌کند. در مثال‌ها یک پرانتز اضافه که چیزی را گروه‌بندی نمی‌کند هشدار می‌گیرد، ارجاع به گروه سوم وقتی فقط دو گروه capture وجود دارد زیر سؤال می‌رود، و ارجاع به گروهی با نامی که وجود ندارد (در مثال named input یا named import) هم گزارش می‌شود. گوینده هنوز برای نوشتن regex از ابزار خارجی استفاده می‌کند، ولی این بررسی را کیفیت زندگی مفیدی می‌داند.

چهارمی تایپ متدهای تازهٔ Set است: union، intersection، difference و بقیه. در ۵.۴ این نوع‌ها وجود ندارند و خطا می‌دهند؛ در ۵.۵ تایپ‌ها هست و خطا نیست. شرط این است که هدف کامپایل به اندازهٔ کافی جدید باشد. او ESNext را به‌جای چیزی مثل ES6 گذاشته تا آن متدها در جاوااسکریپت مقصد باشند. اگر compiler options این را نداشته باشد، مستقل از نسخهٔ TypeScript خطا می‌گیرید.

## نکات کلیدی

- در ۵.۵ نتیجهٔ filter که null را حذف می‌کند number[] است؛ در ۵.۴ همان آرایه number | null می‌ماند.
- تابع چک‌کنندهٔ نوع، مثلاً نگه داشتن فقط number از میان string و number و null، در ۵.۵ نوع خروجی filter را درست می‌کند.
- باریک شدن مقدار Record بعد از if در ۵.۵ بدون متغیر کمکی کار می‌کند؛ در ۵.۴ باید مقدار را اول در متغیر ریخت.
- ۵.۵ داخل regex را می‌بیند: پرانتز بی‌استفاده، شمارهٔ گروه capture که وجود ندارد، و نام گروهی که تعریف نشده.
- متدهای Set مثل union و intersection و difference فقط وقتی تایپ دارند که هدف زبان به اندازهٔ کافی جدید باشد.
- با هدف قدیمی، حتی روی TypeScript 5.5 هم برای این متدها خطا می‌ماند؛ گوینده ESNext را مثال می‌زند.
- دو مورد اول بیشتر بهبود استنباط‌اند و بررسی regex و تایپ Set قابلیت تازه‌تری برای کار روزمره‌اند.

## برش‌های مهم

- filter از نظر نوع هیچ‌وقت آن‌طور که انتظار دارید آرایه را صافی نمی‌کرد و هنوز احتمال null را نگه می‌داشت.
- قبلاً باید متغیری وسط کد می‌گذاشتید تا خطای TypeScript برطرف شود، نه به این خاطر که جاوااسکریپت به آن نیاز داشت.
- TypeScript قبلاً عبارت منظم را کاملاً نادیده می‌گرفت؛ در ۵.۵ اگر الگو مشکوک باشد خبر می‌دهد.
