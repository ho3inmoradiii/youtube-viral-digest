## خلاصه

ویدیوی IBM دو راه برای اضافه کردن قابلیت به مدل را کنار هم می‌گذارد: سرور MCP و skill. مدل را مثل گوی پیش‌بینی توصیف می‌کند که روی کتاب و مجله و شاید رشته‌های اینترنتی آموزش دیده و با تشخیص الگو به خیلی سؤال‌ها جواب می‌دهد، از تاریخ Red Hat تا نحوهٔ وارسی یک پایگاه. دانستن کلی کافی نیست؛ جواب درست یعنی زمینهٔ درست. آن زمینه می‌تواند قالب خروجی، پیکربندی پایگاه مخصوص تیم، یا پاسخ ابزاری باشد که واقعاً رفته و از پایگاه چیزی آورده و به پنجرهٔ زمینه برگردانده. سؤال با یک نقش و یک وظیفه همان پرامپت‌نویسی است. وقتی این اطلاعات اضافه وارد می‌شود، نامش مهندسی زمینه است: دادن هر چه مدل برای جواب درست لازم دارد.

اگر ایجنت به دادهٔ داخل CRM نیاز داشته باشد، راه‌نایاب این است که مستندات API و توکن را کپی کنید و بگویید اطلاعات تماس مشتری را بی‌خطا به‌روز کن. MCP به‌جای این کار، حرف زدن مدل با منبع داده را استاندارد می‌کند. API سرویس را به قالب آمادهٔ مدل انتزاع می‌کند و احراز هویت را هم جلو می‌برد: توکن با دامنهٔ مشخص و دسترسی خواندن یا نوشتن، هر چه لازم است. سرور MCP به IDE یا اپ هوش مصنوعی اضافه می‌شود، به مدل می‌گوید برای اطلاعات لازم درخواست JSON بدهد، و خودش آن را به POST یا GET سرویس ترجمه می‌کند. لایهٔ استاندارد بین مدل و منبع است و می‌گوید تقریباً همهٔ ابزارهای هوش مصنوعی از آن پشتیبانی می‌کنند.

MCP دادهٔ بیرونی را حل می‌کند ولی دانش حوزه‌ای که مدل ندارد هنوز جا می‌ماند. مدل‌ها غیرقطعی‌اند، در حالی که تیم فروش می‌خواهد دادهٔ CRM هر بار دقیقاً یک شکل باشد: نام، اطلاعات تماس، و مثلاً نوع کلوچهٔ محبوب مشتری. skill برای همین تکرارپذیری است و روی ابزارها و مدل‌های اصلی کار می‌کند. کارهایی که همیشه با مدل انجام می‌دهید، مثل تمیز کردن اکسل، دیباگ کدی که معمولاً با آن صحت را چک می‌کنید، یا کنترل انطباق، به‌همراه پرامپت و اسکریپت‌هایشان در یک skill بسته می‌شوند: در اصل یک فایل مارک‌داون با کمی فراداده داخل یک پوشه. ساختارش عنوان، توضیح اینکه کی به کار بیاید، و خود پرامپتی است که به مدل می‌رسد. ویژگی مهم این است که در صورت نیاز خودش وارد پنجرهٔ زمینه می‌شود؛ مثلاً مهارت دیباگ کد فقط وقتی سؤال از خطای کد است بارگذاری می‌شود. داخل همان پوشه می‌شود منبع و اسکریپت اضافه کرد تا با همان قابلیت خودکار بیایند.

انتخاب: اگر اپ به دادهٔ لحظه‌ای با مجوز سفت نیاز دارد، MCP مناسب است. آن را یکپارچگی ایجنت و ابزار می‌داند که فقط ابزار و منبع اعلام‌شده را صدا می‌زنید. مثال‌ها: الان چه ماشین‌مجازی‌هایی روشن است، وضعیت کلاستر چیست، یا اطلاعات یک مشتری. اگر فقط یک قابلیت تکراری و سفارشی می‌خواهید، راه‌اندازی MCP زیاده‌روی است و skill سبک‌تر است، چون به مدل یاد می‌دهد کاری را چطور انجام دهد، مثلاً دادهٔ سرمایه‌گذاری را بیاورد و تحلیل کند، با اسکریپت و مثالی که داخل خود skill است. هر دو پنجرهٔ زمینه را غنی می‌کنند، هر دو متن‌باز و در بیشتر ابزارهای امروز رایج‌اند، و می‌شود همین حالا محلی شروع کرد. مقایسه با CLI برای ساخت ایجنت را به ویدیوی بعدی موکول می‌کند.

## نکات کلیدی

- پرامپت یعنی وظیفه و نقش. مهندسی زمینه یعنی بقیهٔ اطلاعاتی که جواب درست را ممکن می‌کند، از جمله پاسخ ابزار.
- MCP به‌جای چسباندن مستندات API و توکن، سرویس را به درخواست JSON آمادهٔ مدل و توکن دامنه‌دار ترجمه می‌کند و احراز هویت را استاندارد می‌کند.
- سرور، JSON مدل را به POST یا GET سرویس واقعی بدل می‌کند. ویدیو می‌گوید تقریباً همهٔ ابزارهای هوش مصنوعی از این لایه پشتیبانی می‌کنند.
- skill برای کار تکراری و غیرقطعی‌نبودن خروجی است: مارک‌داون به‌علاوهٔ فراداده در یک پوشه، با عنوان و شرح زمان استفاده و خود پرامپت.
- مهارت فقط وقتی به موضوعش مربوط باشد وارد زمینه می‌شود و می‌تواند اسکریپت و منبع همراه داشته باشد.
- دادهٔ لحظه‌ای با دسترسی کنترل‌شده، مثل VM و وضعیت کلاستر و مشتری، کار MCP است. قابلیت سبک و آموزشی کار skill است.
- هر دو متن‌باز هستند و ویدیو می‌گوید می‌شود همین امروز روی ماشین خودتان از هر دو استفاده کرد.

## برش‌های مهم

- دادن یک وظیفه به مدل پرامپت‌نویسی است؛ آوردن قالب و پیکربندی و پاسخ ابزار به پنجرهٔ زمینه، مهندسی زمینه است.
- MCP مسئلهٔ دادهٔ بیرونی را استاندارد می‌کند، ولی هنوز باید به مدل دانش حوزه‌ای بدهید که شاید از قبل نداشته باشد.
- اگر فقط می‌خواهید مدل یک کار را هر بار به یک شکل بلد باشد، راه‌اندازی MCP زیاد است و skill سبک‌تر همان کار را یاد می‌دهد.
