## خلاصه

ویدیو MCP را هم ساده و هم فنی توضیح می‌دهد و هیاهو را از وضعیت اولیه جدا می‌کند. سیر را این‌طور می‌بیند: اول LLM بدون ابزار، بعد چارچوب‌های عاملی که مدل از ابزار و دانش کمک می‌گیرد، و حالا روش استاندارد حرف زدن با همان ابزار و دانش تا ساخت اپ آسان‌تر شود. مثال، تحلیلگر سهام است که گزارشی برای مقایسهٔ انویدیا و تسلا می‌خواهد: معرفی شرکت، سنجهٔ مالی، خلاصهٔ سنجه‌ها، و خبر تازه. دوست مهندسش می‌داند مدل معرفی دو شرکت را از دادهٔ آموزش بلد است ولی قیمت لحظه‌ای سهام را نه. اگر قیمت یک‌بار رسیده باشد، خلاصه کردنش کار مدل است. وقتی در ChatGPT جواب تازه دیده می‌شود، در واقع خود ChatGPT در حال جست‌وجوی وب است و ایجنت است؛ گوینده مشخصاً به مدل GPT-4o اشاره می‌کند. مهندس باید ابزارهایی مثل API یاهو فایننس یا جست‌وجوی وب، به‌علاوهٔ دانش خصوصی مثل PDFهای داخل شرکت، را با glue code به مدل وصل کند. این glue code یا داخل چارچوب عاملی مثل CrewAI و امثال آن نوشته می‌شود یا دستی در کد پایتون یک گردش کار. اگر شرکت ۲۰ اپ شبیه این بسازد و شرکت‌های دنیا میلیون‌ها اپ، حجم این کد چسب و نگهداری‌اش کابوس است، چون فردا اگر API یاهو عوض شود همه‌جا باید اصلاح شود. تشبیه، سیم‌های جدا برای کیبورد و ماوس در برابر USB-C است. MCP همان لحظهٔ USB-C است: مدل از راه پروتکل با سرورهای مختلف حرف می‌زند و مثلاً یاهو فایننس یا جست‌وجوی گوگل ابزار و منبع و پرامپت را پشت سرور خودشان می‌گذارند. هنوز کمی کد چسب لازم است، ولی نوشتن و نگه‌داشتنش آسان‌تر است و سازندهٔ سرویس یک بار سرور را می‌نویسد. می‌گوید حدود ۱۰ هزار برنامه‌نویس دیگر لازم نیست هر کدام همان اتصال را از نو بنویسند.

جزئیات فنی با یک چت‌بات سازمانی است که مکان را از گوگل‌مپ می‌گیرد و کار را در Todoist می‌سازد، و هر دو تیم از قبل سرور MCP دارند. کلاینت پیکربندی سرورهای در دسترس را دارد. هنگام شروع، برای هر سرور list tools می‌زند. سرور قابلیت‌ها را با توضیح برمی‌گرداند. توضیح مهم است چون مدل فقط با خواندنش می‌فهمد برای جست‌وجوی مکان باید ابزار جست‌وجوی نقشه را صدا بزند و پارامترهایی مثل عبارت جست‌وجو و طول و عرض را از سؤال طبیعی دربیاورد. توضیح ابزارهای Todoist هم کنار همان فهرست است. پرامپت به مدل می‌گوید از روی سؤال کاربر ابزار مناسب را انتخاب کند. کلاینت نمونه از SDK پایتون انتروپیک، موقع شروع همهٔ سرورها را می‌گردد، list tools می‌گیرد و توضیح‌ها را داخل پرامپت می‌گذارد.

سرور نمونهٔ گوگل‌مپ با TypeScript نوشته شده، هرچند سرور را می‌شود با پایتون هم ساخت. ابزارهایی مثل search places و geocode را فهرست می‌کند و داخل تابع در واقع HTTP به API گوگل‌مپ می‌زند. MCP جایگزین REST نیست؛ لفاف است و پاسخ را در قالب استاندارد برمی‌گرداند. input schema برای توضیح ابزار و پارامترها بخشی از همین استاندارد است و هر سازندهٔ سرور باید به آن پایبند باشد. هر سرور سه قابلیت دارد: tool و resource و prompt. SDK پایتون برای هر کدام مثال ساده دارد. ابزار نمونه fetch یک وب‌سایت را با HTTP می‌خواند. منبع، دانش است مثل فایل یا پایگاه؛ مثال ساده یک فایل معمولی است و می‌شود فایل روی درایو یا چیزی مثل S3 باشد. کلاینت هنگام شروع list tools و list resources و list prompts را برای هر سرور صدا می‌زند تا قابلیت کامل را بداند. پرامپت‌ها را خود سازندهٔ API، که می‌داند مهندس‌ها چه پرسش‌هایی لازم دارند، روی سرور می‌گذارد تا نوشتن پرامپت برای کلاینت آسان شود. مثال یک پرامپت است که context و topic می‌گیرد و متن را با همان دو تا می‌سازد.

جمع‌بندی این است که پتانسیل زیاد است ولی هنوز روزهای اول است. هیجان را قبول دارد و همزمان می‌گوید واقعیت و هیاهو با هم قاطی است و باید دید این پروتکل چطور برای مسئلهٔ واقعی مهندس‌ها تکامل پیدا می‌کند. قول آموزش‌های بعدی برای ساخت سرور و کلاینت واقعی را می‌دهد.

## نکات کلیدی

- قبل از MCP هر اپ glue code خودش را به API و دانش خصوصی می‌چسباند و با عوض شدن API باید همان کد نگهداری شود.
- مدل معرفی انویدیا و تسلا را از آموزش بلد است، نه قیمت لحظه‌ای. جست‌وجوی وب داخل ChatGPT را رفتار ایجنتی روی GPT-4o می‌داند، نه دانش خالص مدل.
- MCP را USB-C این اتصال‌ها می‌داند. سرویس یک بار سرور را می‌نویسد و بقیه به‌جای هزاران پیاده‌سازی تکراری از همان استاندارد استفاده می‌کنند.
- کلاینت هنگام شروع list tools می‌زند. توضیح ابزار به مدل می‌گوید کدام تابع و کدام پارامتر را از سؤال طبیعی دربیاورد.
- سرور گوگل‌مپ در مثال TypeScript است و داخلش HTTP به API نقشه می‌زند. MCP جای REST را نمی‌گیرد.
- سه قابلیت اجباری در چارچوب ویدیو: ابزار، منبع، و پرامپت. طرح ورودی بخشی از استاندارد است.
- گوینده هیجان را واقعی می‌داند ولی تأکید می‌کند هنوز اوایل کار است و اثر عملی‌اش باید با زمان معلوم شود.

## برش‌های مهم

- مشکل فقط نوشتن glue code نیست؛ فردا اگر API عوض شود نگهداری همان کد کابوس می‌شود.
- MCP جایگزین پروتکل REST نیست. لفاف است و داخلش همان API را صدا می‌زند و جواب را استاندارد برمی‌گرداند.
- هیاهو زیاد است و پتانسیل هم هست، ولی هنوز روزهای اول است و باید دید مسئلهٔ واقعی را چطور حل می‌کند.
