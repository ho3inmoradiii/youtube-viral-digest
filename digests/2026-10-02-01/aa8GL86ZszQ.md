## خلاصه

ویدیو سرور MCP تازه‌منتشرشدهٔ Chrome DevTools را از زاویهٔ یک درد قدیمی طراحی در مرورگر نشان می‌دهد: در Cursor با live reload کار می‌کنید، در Chrome یک ویژگی CSS را در DevTools عوض می‌کنید، صفحه را refresh می‌کنید و تغییر در فایل ذخیره نمی‌شود. ادعای گوینده این است که همین سرور MCP آن فاصله را پر می‌کند.

راه‌اندازی در Cursor با مشخص کردن Chrome DevTools در همان بخش اتصال MCP است؛ او به چهار خط تنظیم اشاره می‌کند. روی Windows 11 برای خودش کار نمی‌کرد چون Node روی نسخهٔ ۲۲ بود و می‌گوید باید بالاتر از ۲۲ باشد، مثلاً ۲۳. در دمو ابتدا از Figma با «copy link to selection» و سرور MCP فیگما یک منوی کشویی را داخل index.html می‌سازد، بعد از DevTools MCP می‌خواهد همان فایل را باز کند. Chrome با پیام کنترل توسط نرم‌افزار تست خودکار بالا می‌آید، نه مثل پنجرهٔ معمولی.

در Elements رنگ پس‌زمینه را عوض می‌کند و refresh می‌زند؛ تغییر می‌پرد. بار دوم همان تغییر را در inspector می‌گذارد، refresh نمی‌کند، و در Cursor می‌نویسد که در بازرس Chrome یک تغییر CSS داده و باید به کد منتقل شود. MCP ویژگی‌ها را با index.html مقایسه می‌کند و تفاوت را در کد می‌نویسد؛ بعد از refresh رنگ می‌ماند. فایده وقتی است که ویژگی‌ها زیادند و CSS بین کامپوننت‌ها پخش است و جست‌وجوی فایل کند است. شرطش این است که قبل از سپردن کار به Cursor صفحه را refresh نکنید، وگرنه تغییرها از دست می‌روند. بعد از آن، بسته به ساختار پروژه، تغییرها در فایل لازم پایدار می‌شوند.

گوینده می‌گوید این سرور ۲۶ ابزار دارد. نمونهٔ دوم: «روی منوی کشویی active کلیک کن و آن را به گزینهٔ disabled عوض کن.» عامل click را صدا می‌زند، snapshot می‌گیرد، disabled را پیدا می‌کند و موفق بودن را تأیید می‌کند. می‌شود به فیلد متن نوشت و ارسال کرد و خطاهای کنسول را از روی همین آزمون کاربری دید. Playwright هم کار مشابه می‌کند، ولی این یکی از خود Chrome است. جمع‌بندی او این است که اصلاح ریز طراحی را در مرورگر انجام می‌دهد و از Cursor می‌خواهد همان را پیدا و در کد واقعی پایدار کند.

## نکات کلیدی

- مسئله این است که ویرایش CSS در DevTools با refresh به فایل پروژه برنمی‌گردد.
- در Cursor اتصال با چند خط تنظیم Chrome DevTools MCP است؛ گوینده برای کارکردن روی ویندوز Node بالاتر از ۲۲، مثلاً ۲۳، لازم داشته است.
- Chrome بازشده توسط MCP پیام «controlled by automated test software» را نشان می‌دهد.
- با گفتن اینکه تغییر در inspector داده شده، MCP تفاوت را با کد، در مثال index.html، مقایسه و ذخیره می‌کند.
- قبل از این درخواست نباید refresh کرد، وگرنه ویرایش‌های inspector پاک می‌شوند.
- در پروژهٔ بزرگ، لازم نیست بین فایل‌های پراکندهٔ CSS دنبال همان ویژگی بگردید.
- از ۲۶ ابزار، نمونهٔ کلیک روی dropdown و عوض کردن گزینه به disabled با click و snapshot و تأیید نتیجه نشان داده می‌شود؛ پر کردن فیلد و دیدن خطای کنسول هم جزو کاربردهاست.

## برش‌های مهم

- تغییر CSS در Chrome را refresh می‌کنید و در فایل ذخیره نمی‌شود؛ MCP همان را به کد برمی‌گرداند.
- اگر ویژگی زیاد است و CSS همه‌جا پخش است، سریع‌تر است در inspector طراحی کنید و بعد بخواهید تفاوت‌ها کشیده شوند.
- تا وقتی refresh نزده‌اید تغییرها هستند؛ بعد به Cursor می‌گویید آن‌ها را در ساختار پروژه پایدار کند.
