## خلاصه

ویدیو Core Web Vitals را از زاویهٔ سئو و تجربهٔ کاربر توضیح می‌دهد، با همان سه معیار قدیمی‌تر: Largest Contentful Paint، First Input Delay و Cumulative Layout Shift. گوینده می‌گوید گوگل Web Vitals را ساخته تا عملکرد سایت‌ها در کل وب یک استاندارد داشته باشد. آن استاندارد از دادهٔ واقعی کاربران در Chrome UX Report، یا CrUX، آمده: کروم هنگام وب‌گردی کاربران دادهٔ عملکرد جمع کرده، یک خط پایه ساخته و آن را عمومی کرده است. Web Vitals نشان می‌دهد سایت شما در هر محور نسبت به بقیهٔ اینترنت پایین‌تر یا بالاتر است. صفحهٔ پر از پارالاکس و تصویر خیلی سنگین ممکن است روی ماشین خودتان خوب باشد و برای کاربر اینترنت تجربهٔ دیگری بسازد.

از سال ۲۰۲۰ گوگل اعلام کرده Web Vitals به‌طور دسته‌بندی‌شده روی رتبه در صفحهٔ نتایج جست‌وجو اثر می‌گذارد، پس بخشی از سئو شده است. استدلال ویدیو این است که اگر نتایج صفحهٔ اول بیش از ۲۰ ثانیه طول بکشند، آدم‌ها جست‌وجو را رها می‌کنند. سه Core Web Vital را آن‌هایی می‌داند که هم رتبه و هم تجربه را جدی تکان می‌دهند.

LCP زمان رسیدن بزرگ‌ترین قطعهٔ محتواست و بارگذاری را می‌سنجد. توصیه این است که در ۲٫۵ ثانیهٔ اول بعد از درخواست بارگذاری اتفاق بیفتد؛ یعنی کسی که از گوگل کلیک می‌کند باید بزرگ‌ترین محتوا را در کمتر از دو و نیم ثانیه ببیند. گوینده به نقل از گوگل می‌گوید اگر صفحه زیر ۳ ثانیه بالا نیاید، ۵۳ درصد کاربران فوراً برمی‌گردند، و این بازگشت برای گوگل سیگنال بی‌علاقگی و دلیلی برای پایین آوردن رتبه است. مقصرهای معمول را حجم فایل بیش از حد، تصویر فشرده‌نشده و هاست ضعیف می‌داند و می‌گوید برای اطمینان باید بیشتر بررسی کرد.

FID فاصلهٔ تلاش کاربر برای تعامل تا لحظه‌ای است که سایت واقعاً می‌تواند event handler را پردازش کند. برای فرم، لینک یا هر چیز تعاملی، توصیه کمتر از ۱۰۰ میلی‌ثانیه است؛ بیشتر از آن احتمالاً حس می‌شود و کاربر سایت را رها می‌کند یا برنمی‌گردد. دلیل رایج را جاوااسکریپت تک‌نخی و یک call stack می‌داند: تا کار فعلی تمام نشود خط بعدی اجرا نمی‌شود، پس فایل جاوااسکریپت بزرگ صفحه را تا پایان آن کار منجمد می‌کند.

CLS پایداری بصری و جابه‌جایی‌های غیرمنتظرهٔ چیدمان را می‌سنجد. گوگل دو اندازه می‌گیرد: impact fraction یعنی چند درصد viewport جابه‌جا شده، و distance fraction یعنی لبهٔ عنصر بعد از جابه‌جایی کجا می‌نشیند. هر دو درصدند و ضربشان امتیاز جابه‌جایی است. بزرگ‌ترین امتیاز در طول عمر صفحه، امتیاز CLS است. توصیه حداکثر ۰٫۱ است و گوینده این را این‌طور معنی می‌کند که عنصرها نباید بیش از ۱۰ درصد عرض viewport جابه‌جا شوند. مقصر رایج را CSS بد، انیمیشن بدون برنامه، یا CSS داخل جاوااسکریپتی می‌داند که دیر اجرا می‌شود و به خاطر همان call stack چند ثانیه دیرتر می‌رسد. در پایان Sematext Experience و Sematext Synthetics را برای پایش چند سایت، هشدار و گزارش حادثه معرفی می‌کند و به آزمایش رایگان ارجاع می‌دهد.

## نکات کلیدی

- Web Vitals مجموعهٔ معیارهای گوگل است و خط پایه‌اش از دادهٔ واقعی CrUX می‌آید، نه فقط تست روی ماشین خودتان.
- از ۲۰۲۰ این معیارها روی رتبهٔ جست‌وجو اثر دارند؛ سه مورد اصلی این ویدیو LCP و FID و CLS هستند، نه INP.
- LCP خوب: حداکثر ۲٫۵ ثانیه. ادعا می‌شود اگر بارگذاری زیر ۳ ثانیه نباشد، ۵۳ درصد کاربران فوراً برمی‌گردند.
- FID خوب: کمتر از ۱۰۰ میلی‌ثانیه. جاوااسکریپت تک‌نخی و باندل سنگین صفحه را تا تمام شدن کار جاری قفل می‌کند.
- CLS خوب: حداکثر ۰٫۱. امتیاز از ضرب سهم viewportِ درگیر در مسافت جابه‌جایی به دست می‌آید.
- تصویر حجیم و هاست ضعیف بیشتر به LCP می‌خورند؛ CSS دیر یا انیمیشن بد بیشتر به CLS.
- ویدیو در پایان ابزارهای خود Sematext را برای مانیتورینگ و آلرت پیشنهاد می‌کند.

## برش‌های مهم

- چیزی که روی سیستم خودتان نرم بالا می‌آید، برای کاربر واقعی اینترنت می‌تواند تجربهٔ کاملاً دیگری باشد.
- اگر صفحه زیر ۳ ثانیه بارگذاری نشود، به گفتهٔ ویدیو ۵۳ درصد کاربران همان لحظه برمی‌گردند و گوگل این را سیگنال رتبه می‌بیند.
- تا وقتی فایل بزرگ جاوااسکریپت روی تنها call stack تمام نشده، صفحه برای تعامل بعدی منجمد است.
