## خلاصه

ویدیو نشان می‌دهد انیمیشن جابه‌جایی تصویر بین دو صفحه، شبیه hero در iOS و Android، با View Transitions تقریباً در دو خط ممکن شده است. گوینده حدود یک سال قبل پلتفرم دورهٔ fireship.io را با Svelte و Hugo و روتر دست‌ساز Flamethrower ساخته بود. آن زمان Astro را کنار گذاشت چون مسیریابی سمت کلاینت که state جاوااسکریپت را بین مسیرها نگه دارد نداشت؛ Astro با هر لینک کل صفحه را از نو بارگذاری می‌کرد، بر خلاف Next و Nuxt و SvelteKit. برای وبلاگ کوچک اشکالی ندارد، ولی برای سایتی با احراز هویت و پیگیری پیشرفت و پخش ویدیو سخت است.

چند روز قبل از ضبط، Astro یک View Transitions API منتشر کرده که روی API هم‌نام مرورگر سوار است. خود API آزمایشی است و همه‌جا پشتیبانی نمی‌شود، ولی Astro برای مرورگرهای بدون پشتیبانی fallback دارد. گوینده می‌گوید اگر امروز fireship.io را از نو بسازد احتمالاً Astro را انتخاب می‌کند: مدیریت محتوا، جاوااسکریپت کمتر، و امکان ترکیب چند فریم‌ورک. یک پروژهٔ Astro با همین API هم به تولید رسیده؛ در مستندات sveltefire بین مسیرها fade دیده می‌شود و کنسول soft navigation را گزارش می‌کند. پیاده‌سازی این است که کامپوننت ViewTransitions به layout اصلی import و داخل head گذاشته شود. در DevTools یک شبه عنصر view-transition دور کل صفحه برای همان fade اضافه می‌شود.

بده‌بستان‌ها هم گفته می‌شود. حدود ۴.۵ کیلوبایت جاوااسکریپت لازم است؛ روی بارگذاری اثر محسوسی ندارد، ولی دیگر نمی‌شود ادعا کرد صفر جاوااسکریپت به کلاینت رفته. رفتار شبیه Turbolinks است: اسکریپتی که قبلاً در هر صفحه اجرا می‌شد حالا یک بار اجرا می‌شود. در سایت گوینده حالت روشن و تیره با localStorage فقط در بار اول درست کار می‌کرد و بعد از ناوبری نرم به حالت روشن برمی‌گشت. راه‌حل، گوش دادن به رویداد before-load خود Astro است تا در هر ناوبری نرم کلاس درست دوباره اعمال شود. دکمه‌های ناوبری بالا هم بعد از جایگزینی DOM شنونده‌شان را از دست می‌دادند؛ به‌جای بستن دوبارهٔ listener، دستور transition:persist روی ریشهٔ کامپوننت عنصر و state و شنونده‌ها را به صفحهٔ بعد می‌برد و با معماری جزیرهٔ Astro جور است. اگر همان کامپوننت جای دیگری باشد می‌شود برای transition اسم گذاشت.

انیمیشن مسیر هم ساده است. پیش‌فرض fade است. با transition:animate و مقدار slide روی main، محتوا از راست وارد و به چپ خارج می‌شود و رفتار پیش‌فرض را می‌شود کاملاً سفارشی کرد. نمونهٔ کتابخانهٔ موسیقی Astro جلد آلبوم را از فهرست به صفحهٔ تک‌آلبوم می‌برد بدون اینکه تصویر از صفحه غیب شود. دموی خود ویدیو شبکه‌ای از تصویر است که هر کدام به صفحهٔ اختصاصی همان تصویر لینک می‌شود؛ نام transition روی بندانگشتی و روی تصویر صفحهٔ جزئیات یکی است تا API بداند کدام عنصر را به کدام عنصر تبدیل کند.

## نکات کلیدی

- View Transitions در Astro روی API آزمایشی مرورگر است و برای مرورگرهای بدون پشتیبانی fallback دارد.
- افزودن کامپوننت ViewTransitions به head همان fade بین مسیرها را فعال می‌کند و کنسول soft navigation را نشان می‌دهد.
- هزینه حدود ۴.۵ کیلوبایت جاوااسکریپت است و اسکریپت صفحه، مثل Turbolinks، بعد از ناوبری اول دوباره اجرا نمی‌شود.
- رویداد before-load در Astro اسکریپت تم را بعد از ناوبری نرم دوباره اجرا می‌کند.
- transition:persist عنصر، state و event listener را به صفحهٔ بعد منتقل می‌کند.
- transition:animate با slide محتوای main را از راست به چپ می‌برد و انیمیشن پیش‌فرض قابل سفارشی‌سازی است.
- نام یکسان transition روی بندانگشتی و تصویر صفحهٔ بعد، hero animation را بدون جاوااسکریپت جدا می‌سازد.

## برش‌های مهم

- اگر امروز fireship.io را از نو می‌ساخت، به‌خاطر همین قابلیت سراغ Astro می‌رفت.
- با View Transitions دیگر نمی‌شود به ارسال صفر جاوااسکریپت به کلاینت افتخار کرد؛ حدود ۴.۵ کیلوبایت لازم است.
- نام transition به API می‌گوید تصویر را از صفحهٔ فهرست چطور به جای خودش در صفحهٔ بعد ببرد.
