## خلاصه

گوینده می‌گوید بعد از ویدیوی قبلی که با Vite و Module Federation یک میکروفرانت‌اند ساخته، زیر همان ویدیو کامنتی خواسته مدیریت state را نشان بدهد. خروجی این قسمت یک فروشگاه آنلاین کوچک با دو اپ remote و host است و ارتباط‌شان را event-driven می‌گذارد.

دلیل سختی کار را این می‌داند که در مونولیت همه‌چیز در یک زمینهٔ جاوااسکریپت است، ولی میکروفرانت‌اندها جدا هستند. هر اپ زمینهٔ جاوااسکریپت خودش، حافظهٔ مستقل، چرخهٔ استقرار متفاوت، و احتمالاً فریم‌ورک متفاوت دارد. Redux یا React context از این مرز رد نمی‌شوند، چون نمی‌شود استور یک اپ را در اپ دیگر import کرد. localStorage واکنشی نیست. پارامترهای URL خیلی محدودند. صدا زدن API برای هر تغییر state هم کند است هم پیچیده. چیزی که می‌خواهد هم‌زمان، واکنشی، مستقل از فریم‌ورک، با اتصال شل، و از نظر کارایی قابل‌قبول باشد.

راه‌حل را معماری pub/sub رویدادمحور می‌داند. به‌جای حرف زدن مستقیم، اپ‌ها از یک event bus سراسری رد می‌شوند. مثلاً remote محصول را به سبد اضافه می‌کند و رویداد می‌فرستد؛ host گوش می‌دهد و رابط را به‌روز می‌کند. نتیجه از نظر او جداسازی، استقلال از فناوری، مقیاس‌پذیری و قابل‌تست بودن است.

پیاده‌سازی با یک پوشهٔ shared شروع می‌شود. نکته‌ای که حیاتی می‌خواند این است که event bus را به‌صورت singleton روی آبجکت window می‌گذارد تا همهٔ میکروفرانت‌اندها همان نمونه را ببینند. کلاس event bus در سازنده فهرست رویدادها را آماده می‌کند و دو متد on و emit دارد. اگر هنوز ساخته نشده باشد یکی می‌سازد و همان را export می‌کند. اسم رویدادها را هم جدا در یک آبجکت بیرون می‌دهد تا کد خواناتر شود. در on اول چک می‌کند اسم رویداد رشتهٔ معتبر باشد؛ اگر رویداد وجود نداشته باشد آرایهٔ خالی برای callbackها می‌سازد و callback را به آن اضافه می‌کند. برای پاک‌سازی، اگر هنوز شنونده مانده باشد آرایهٔ تازه‌ای بدون همان callback می‌سازد. emit هم اسم را چک می‌کند، یک console.log می‌گذارد تا معلوم باشد چه چیزی منتشر شده، اگر رویداد وجود داشته باشد روی callbackها حلقه می‌زند و داده را به هر کدام می‌دهد، و اگر جایی خطا شود در catch خطا را پرتاب می‌کند.

state فروشگاه در فایل useStore است، به‌همراه هوک useCartStore که هر دو اپ برای کار با محصول از آن استفاده می‌کنند. اگر state سبد روی window هنوز ساخته نشده باشد، items و listeners را آرایهٔ خالی می‌گذارد. تابع notifyListeners اعلان را debounce می‌کند تا آپدیت‌های پشت‌سرهم اسپم نشود: اعلان معلق را لغو می‌کند، ۱۰ میلی‌ثانیه صبر می‌کند، تعداد کل را از جمع quantityها حساب می‌کند، قیمت کل را از ضرب قیمت در تعداد هر آیتم، یک آبجکت با کپی آیتم‌ها به‌علاوهٔ همین جمع‌ها می‌سازد، شنونده‌ها را با مدیریت خطا صدا می‌زند و در آخر رویداد به‌روزرسانی سبد را از event bus منتشر می‌کند. می‌گوید این تأخیر کوتاه باعث می‌شود اگر کسی سریع چند کالا اضافه کند، رابط یک‌بار در پایان عوض شود نه اینکه با هر کلیک چشمک بزند. اگر state هنوز مقداردهی نشده باشد پرچم را true می‌کند و به رویدادهای افزودن کالا، حذف، تغییر تعداد، خالی کردن سبد، و درخواست state گوش می‌دهد. آخر هر کدام notifyListeners صدا زده می‌شود. هوک این‌ها را بیرون می‌دهد: آیتم‌های سبد، تعداد کل، قیمت کل، وضعیت loading، و تابع‌های افزودن، حذف، تغییر تعداد و خالی کردن.

در هدر host از همین هوک تعداد و قیمت را روی دکمهٔ سبد نشان می‌دهد، روی آیتم‌ها حلقه می‌زند، و پایین‌تر هم جمع را با دو دکمهٔ رفتن به تسویه‌حساب و ادامهٔ خرید نشان می‌دهد. در remote، برای دمو، منطق را داخل خود کامپوننت App گذاشته: چند محصول را hardcode کرده، تعداد را از آیتم‌های سبد می‌خواند، و دکمهٔ هر کارت همان افزودن به سبد را صدا می‌زند. در کانفیگ Vite باید import پوشهٔ shared درست شود. این پوشهٔ محلی فقط برای ستاپ روی ماشین خود اوست؛ اگر بخواهد جای دیگری باشد می‌شود پکیج npm جدا که در هر میکروفرانت‌اند نصب شود. در host وجود بخش shared را اختیاری می‌داند، ولی expose کردن event bus و useCartStore از shared را برای کار کردن کل مجموعه ضروری می‌داند. در مرورگر اول remote را build و بعد preview می‌کند، بعد همین کار را برای host. هدر تعداد و قیمت سبد را نشان می‌دهد و پایین محصولات هستند. با افزودن، حالت loading دیده می‌شود، عدد سبد یک می‌شود، لاگ دادهٔ emit در کنسول می‌آید و سبد به‌روز است. چند قلم دیگر اضافه می‌کند، حذف می‌کند، چندتا را یکی‌یکی تا سه قلم می‌رساند و یکی را پاک می‌کند. یادآوری می‌کند بخش محصولات remote است که داخل host میزبانی شده و هدر مال host است و state بین این دو مشترک است.

## نکات کلیدی

- Redux و React context از مرز میکروفرانت‌اند رد نمی‌شوند؛ localStorage واکنشی نیست، URL محدود است و API برای هر تغییر state کند و پیچیده است.
- ارتباط از راه event bus سراسری است که به‌صورت singleton روی window می‌نشیند تا host و remote همان نمونه را ببینند.
- متد on اسم رویداد را چک می‌کند، در صورت نبود آرایهٔ شنونده می‌سازد و موقع پاک‌سازی همان callback را برمی‌دارد؛ emit داده را به شنونده‌ها می‌دهد و خطا را می‌گیرد.
- useCartStore بین هر دو اپ مشترک است و notifyListeners با تأخیر ۱۰ میلی‌ثانیه، تعداد و قیمت کل را یک‌جا حساب می‌کند تا رابط چشمک نزند.
- رویدادهای سبد شامل افزودن، حذف، تغییر تعداد، خالی کردن و درخواست state هستند و هر کدام در پایان شنونده‌ها را خبر می‌کنند.
- هدر host تعداد، قیمت، فهرست سبد و دکمه‌های تسویه و ادامهٔ خرید را نشان می‌دهد؛ remote چند محصول hardcode دارد و دکمهٔ افزودن را صدا می‌زند.
- در Vite باید shared قابل import باشد و host حتماً event bus و هوک سبد را expose کند؛ دمو با build و preview هر دو اپ، حالت loading و رسیدن سبد به سه قلم را نشان می‌دهد.

## برش‌های مهم

- نمی‌شود استور یک اپ را مستقیم در اپ دیگر import کرد.
- اگر چند کالا پشت سر هم اضافه شود، رابط باید یک‌بار در پایان به‌روز شود، نه با هر کلیک.
- هدر مال host است و فهرست محصول مال remote، و هر دو یک state سبد را می‌بینند.
