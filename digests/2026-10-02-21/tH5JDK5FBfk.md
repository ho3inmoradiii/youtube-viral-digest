## خلاصه

جاد جبران در dotJS ۲۰۲۶ می‌گوید وب از هر وقت تواناتر است و این توان بالای صفحه نشسته، ولی خرج نمی‌شود. قصه را سه پرده می‌کند: صفحه بهتر شد، صفحه از تب بیرون زد، تب خودش کامپیوتر شد.

پردهٔ اول HTML و CSS است، نه فریم‌ورک. `dialog`، popover همراه anchor positioning، و select قابل‌سفارشی را primitiveهایی می‌داند که از جاوااسکریپت قابل کنترل‌اند و برای کارایی و دسترس‌پذیری بهتر از ویجت دست‌سازند. بعد کوئری حالت اسکرول را نشان می‌دهد، چیزی که در سالن برای خیلی‌ها تازه بود: استایل دادن وقتی عنصر به سر یا ته اسکرول رسیده، وقتی scroll-snap شده، یا وقتی `position: sticky` گیر کرده، بدون جاوااسکریپت.

View Transitions را baseline تازه‌موجود و بین مرورگرها خواند. نکته‌ای که روش تأکید کرد عبور انیمیشن بین دو صفحهٔ جدا روی یک دامنه‌است، نه بین دو state داخل یک SPA. در دمو از `index.html` به `app.html` می‌رود. همان `view-transition-name` باید دو طرف باشد و ناوبری view transition روشن شود تا مرورگر از عنصر عکس بگیرد و به جای جدید ببرد.

پردهٔ دوم خروج از تب است. Document Picture-in-Picture را پنجرهٔ همیشه-رو با HTML دلخواه توصیف کرد و مثال زد: پیش‌نمایش دوره روی مانیتور دوم، یا رسید مشتری روی نمایشگر رو به مشتری. Web app و web push را هم گفت، با این ستاره که روی iOS پوش برای هر سایت باز نیست و سایت باید نصب شده باشد. ته این پرده را به عنصر `a` برمی‌گرداند: لینک هنوز راه سهم‌گذاری تجربه است، و همان گراف لینک را حالا مدل‌ها برای grounding هم به کار می‌برند.

پردهٔ سوم، تب به‌جای کامپیوتر. مثال WebHID: به‌روزرسانی firmware عینک XREAL از صفحه‌ای در مرورگر. File System Access API را با Excalidraw (ذخیره روی دیسک و نوشتن دوباره در همان فایل) و vscode.dev (باز کردن فولدر محلی) گفت، و همان‌جا محدودیت را هم گفت: فایرفاکس و سافاری به این API روی خوش نشان نداده‌اند. Speculation Rules را کوتاه گفت چون خودش را روی پرفورمنس پرحرف می‌داند: با یک تکهٔ کوچک می‌شود صفحهٔ بعدی را pre-render کرد، حتی با جاوااسکریپت. الگوی خودش این است که لندینگ سبک بماند تا کاربر هنوز در حال خواندن باشد و در همان فاصله service worker و pre-render انجام شود.

برای AI داخل مرورگر دو راه گذاشت. Prompt API ساده‌ترین شروع است و از فایرفاکس و سافاری سیگنال مثبت ندارد؛ اگر برای یک origin نصب شود برای بقیه هم در دسترس می‌شود، که به درد پنل ادمین می‌خورد. راه پشتیبان، Transformers در مرورگر برای پوشش بیشتر دستگاه. در دورهٔ learnai.online خروجی پرامپت را در مرورگر چک می‌کند، نه خود پرامپت را، و اگر دستگاه ضعیف باشد یا کاربر پرداخته باشد می‌تواند برود سمت ابر. گفت دور این مدل یک هارنس با skill هم هست. این بخش کوتاه است و وارد جزئیات هارنس نمی‌شود.

دموی آخر declarative partial updates است. مارکری که شکل processing instruction دوران XML را دارد داخل HTML می‌ماند و در همان درخواست، چند صد میلی‌ثانیه بعد، یک `template` استریم می‌شود و جایش را می‌گیرد. مثال عملکردی: مگامنوی چندصدخطی LCP را عقب می‌اندازد؛ بردنش به ته DOM ترتیب تب و دسترس‌پذیری را خراب می‌کند. با مارکر، محتوای LCP زود می‌رسد و منو، حتی اگر به دیتابیس و وضعیت لاگین وصل باشد، در همان پاسخ دیرتر می‌آید. مثال دوم را server-aware partial rendering نامید: اگر پوسته را داری فقط تکهٔ صفحه می‌آید، و اگر reload باشد کل صفحه. گفت فایرفاکس و سافاری به آن مثبت‌اند، ولی خودش آن را برای افتتاح یک کنفرانس پراسترس آمادهٔ پروداکشن نمی‌دانست. بعد رو کرد که کل اسلاید همین یک GET بوده، بدون جاوااسکریپت فرانت، و هر کلیک یک template تازه روی همان درخواست باز می‌فرستد.

جمع‌بندی‌اش این است که دسته‌هایی از نرم‌افزار که کسی فکر نمی‌کرد از دسکتاپ تکان بخورند، مثل طراحی با فیگما، به وب آمده‌اند و نوبت ویدیو و صوت و AI است.

## نکته‌ها

- هیجان جبران برای جایی است که دیگر لازم نیست برای یک primitive رابط، جاوااسکریپت بنویسی.
- «مرورگر دارد» با «هر سه موتور دارند» یکی نیست؛ File System Access و Prompt API را خودش با همین محدودیت گفت.
- دموی partial update را همزمان تحسین و از پروداکشن پراسترس جدا کرد. هر دو جمله مال خود اوست.
- پیش‌رندر صفحهٔ بعدی را مشروط به لندینگ سبک کرد، نه یک تگ جادویی روی هر سایت سنگین.
