## خلاصه

Paperclip را اپ متن‌باز برای ادارهٔ تیم ایجنت معرفی می‌کند. Claude Code یا Codex هنوز خود کدنویسی را می‌کنند. Paperclip دور کار را سازمان می‌دهد: وظیفه، دست‌به‌دست شدن، و سابقه‌ای که بشود برگشت به آن. آداپتر را برای Claude Code و Codex و Gemini CLI و Cursor و OpenCode و Pi نام می‌برد، به‌اضافهٔ مسیر پروسهٔ سفارشی و سرویس HTTP. آداپتر را اتصال شروع ایجنت و جمع کردن نتیجهٔ اجرا می‌گوید. ران‌تایم را هنوز باید خودت پیکربندی کنی. می‌گوید ابزار پیاده‌سازی و ابزار بازبینی را می‌شود جدا انتخاب کرد.

سازمان را شرکت می‌نامد رابط. هدف و پروژه به آن وصل می‌شود. راه‌اندازی سند را با یک ایجنت CEO شروع می‌کند که هدف را می‌خواند، طرح می‌دهد، و کار را واگذار می‌کند. بقیه می‌توانند به او گزارش دهند یا سلسله‌مراتب بزرگ‌تر ساخته شود. آدم بالای این‌ها تصمیم آخر را می‌گیرد. برای اپ ساده می‌گوید احتمالاً شش ایجنت مدیر لازم نیست که بحث کنند فرانت چه کند. هماهنگ‌کننده و چند ایجنت با کار روشن را شروع معقول‌تری می‌داند.

هماهنگ‌کننده وظیفه می‌سازد و به زیردست می‌دهد. ایجنت‌ها به‌روز می‌نویسند و مانع برمی‌گردد بالا. هر issue شرح و کامنت و پیشرفت دارد. فیلتر با وضعیت یا مسئول. checkout جلوی این را می‌گیرد که دو اجرا هم‌زمان همان وظیفه را بردارند. می‌گوید دو وظیفهٔ جدا هنوز می‌توانند به یک کد دست بزنند و فضای کار را هم باید جدا دید. فضای کار ایزوله را آزمایشی می‌گوید: در صورت پیکربندی، برای وظیفه یک git worktree و شاخهٔ جدا. بعدش هنوز باید خودت ترکیب کنی.

مثال را اپ یادداشت محلی می‌گذارد: ساختن، ویرایش، حذف، و ماندن بعد از رفرش. حساب و پرداخت را بیرون از نسخهٔ اول می‌گوید. برای نصب سریع محلی می‌گوید Node 24.11 یا جدیدتر لازم است. فرمان ترمینال در زیرنویس خودکار به‌هم ریخت. گفت Paperclip AI را یک کلمه بنویسند و فرمان دقیق را پایین ویدیو می‌گذارد. این اجرا آن فرمان را از گفتار به‌عنوان دستور قابل‌اجرا نقل نکرد. می‌گوید راه‌اندازی پیش‌فرض Paperclip را محلی بالا می‌آورد و PostgreSQL توکار دارد، پس برای بار اول سرور دیتابیس جدا لازم نیست. اگر آداپتر محلی Claude Code یا Codex است، CLI باید روی همان ماشین نصب و وارد شده باشد. سند آداپتر را پشتیبان ورود با اشتراک موجود و نیز کلید API می‌گوید. کدام حساب استفاده می‌شود به آداپتر بستگی دارد.

اولین ایجنت را با آداپتر و مدل و پوشهٔ کار می‌سازد و قبل از بقیه `test environment` می‌زند. اگر اولی بالا نیاید، چهار تای بعدی فقط چهار دردسر اضافه‌اند. هدف را مشخص می‌گوید: اپ یادداشت محلی با ذخیرهٔ پایدار، تست کار اصلی، و دستور اجرا. وقتی هماهنگ‌کننده طرح می‌دهد، قبل از تأیید می‌خواندش. اگر برای این دمو سرویس بک‌اند و احراز هویت خواست، اصلاح می‌خواهد و نسخهٔ اول را محلی و روی همان رفتار نگه می‌دارد. استخدام پیشنهادی را هم قبل از اضافه کردن ایجنت می‌شود دید و برگرداند.

برای پیاده‌سازی یک مرحلهٔ بازبینی می‌گذارد: آیا یادداشت ساخته و ویرایش می‌شود، حذف همان مورد را برمی‌دارد، رفرش داده را نگه می‌دارد. می‌گوید Paperclip می‌تواند این مرحله را اجباری کند. اگر ایجنت کدنویس بخواهد وظیفه را ببندد، issue به بازبین می‌رود و تغییر درخواستی برمی‌گردد پیش ایجنت اول. مرحلهٔ تأیید نهایی را هم می‌شود گذاشت. تمام شدن از نظر ایجنت را شروع بازبینی می‌داند، نه پایان. برای این مثال می‌خواهد اپ را در حال اجرا ببیند و نتیجهٔ تست را نگاه کند. کیفیت اپ تمام‌شده را هنوز باید جدا سنجید. این را گردش پیشنهادی دمو می‌گوید، نه نتیجهٔ یک اجرای اندازه‌گیری‌شده.

خود Paperclip را رایگان برای میزبانی شخصی و با مجوز MIT می‌گوید. خرج مدل و اشتراک و میزبانی جداست. خرج گزارش‌شده را می‌شود در سطح شرکت، ایجنت، یا پروژه دید. آستانهٔ هشدار و توقف سخت قابل تنظیم است. جزئی که جدا می‌کند: اجرا از روی خرج ثبت‌شده است، و کاری که هنوز در جریان است می‌تواند توقف را عقب بیندازد. بودجه را تضمین این نمی‌داند که صورتحساب ارائه‌دهنده دقیقاً همان عدد شود. خودش یک وظیفهٔ کوچک را اول اجرا می‌کند، مصرف را می‌بیند، بعد جا برای هر ایجنت می‌گذارد. رفت‌وبرگشت بازبین با پیاده‌ساز هم مصرف اضافه می‌کند حتی اگر اپ ساده باشد.

heartbeat ایجنت را بیدار می‌کند. واگذاری و کامنت می‌توانند اجرا را راه بیندازند، و فاصلهٔ زمانی هم قابل تنظیم است. heartbeat زمانی را برای ایجنت تازه پیش‌فرض خاموش می‌گوید. اگر هر چند دقیقه بیدار شود و کاری نباشد، فعالیت ساخته شده بدون حاصل. برای کار تکراری routine جداست: مثلاً خلاصهٔ هفتگی کار تمام‌شده، یا چک issueها هر صبح، با زمان‌بندی یا وب‌هوک. هر اجرا کار قابل‌پیگیری است.

skill مشترک را یک بار می‌نویسی و به ایجنت‌هایی که لازم دارند می‌دهی. مثالش چک‌لیست بازبینی است که قبل از تأیید چه شواهدی جمع شود. Skill Studio را برای ویرایش، تست با ورودی ذخیره‌شده، دیدن خروجی، و برگشت به نسخهٔ قبلی می‌گوید. چک‌لیست مبهم را اگر به همه بدهی همان سردرگمی پخش می‌شود.

اتصال سرویس، از جمله ابزار اپ و MCP سفارشی، را جدا می‌کند. برای اتصال پشتیبانی‌شده می‌شود گفت کدام ایجنت دسترسی دارد و هر عمل allowed یا ask first یا off است. این کنترل‌ها را فقط برای صدایی می‌داند که از دروازهٔ ابزار Paperclip رد می‌شود. هر دستور شل ایجنت کدنویس را خودکار نمی‌بندد. مجوز و اعتبار ران‌تایم را جدا می‌خواهد، مخصوصاً قبل از دادن پروژهٔ واقعی.

توصیه‌اش: اگر چند ایجنت روی کار مرتبط داری و وقتت صرف هماهنگ کردن است، تاریخچهٔ وظیفه و دست‌به‌دست بازبینی را ارزش امتحان می‌داند. اگر بیشتر یک ایجنت برای درخواست کوتاه داری، ساختن کل ساختار شرکت برای عوض کردن چند متغیر را لازم نمی‌داند. عنوان CEO را برای خوب تصمیم گرفتن کافی نمی‌داند. آزمون اولش این است که تیم کوچک اپ یادداشت نتیجه‌ای بدهد که بشود وارسی کرد، با هزینه‌ای که راضی‌اش کند.
