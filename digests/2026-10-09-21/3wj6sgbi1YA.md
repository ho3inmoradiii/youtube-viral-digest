## خلاصه

شرح، Pedro Lopez را مهندس نرم‌افزار Airbyte معرفی می‌کند و لینکدین، گیت‌هاب، و سایت شخصی را فهرست کرده. گفتار اسم کوچک را می‌گوید و شرکت را درهم پیاده می‌کند. زمینه: Airbyte از جابه‌جایی دادهٔ متن‌باز بین ابزارهای SaaS و خط تحلیل شروع کرده و حالا همان را لایهٔ داده و اقدام برای ایجنت می‌داند. Context Store ایندکس جست‌وجوپذیر همان ابزارهاست و بین ایجنت‌ها می‌نشیند. سه رابط: SDK برای کسی که ایجنت خودش را می‌سازد، UI وب، و تمرکز این صحبت که MCP و CLI است تا داده داخل ایجنت موجود، از جمله ChatGPT و Claude، در دسترس باشد.

هر دو رابط باید سه کار را بپوشانند: مدیریت سازمان و ورک‌اسپیس و کانکتور، احراز هویت سرویس سوم بدون دادن رمز به ایجنت، و ask/act یعنی جست‌وجو و خواندن و نوشتن. MCP و CLI را لایهٔ نازک و یکسان روی پلتفرم خواند، نه پیاده‌سازی دوباره. بیشتر سطح‌شان نمایشی است: فرمان را می‌گیرند، پلتفرم را صدا می‌زنند، نتیجه را قالب می‌کنند. گفت پلتفرم روزی بیش از ده بار عوض می‌شود و OpenAPI را منبع حقیقت اتصال گذاشته‌اند.

MCP را برای کاربر غیرفنی دانست که می‌خواهد داده را مستقیم به ChatGPT یا Claude بزند. نصب را یا از لیست فروشگاه، یا با دادن URL میزبانی‌شده. در دمو پرسید چه کانکتورهایی هست. جواب: چهار کانکتور در این ورک‌اسپیس. بعد: پنج مشتری پرداخت‌کننده که تیکت پشتیبانی Zendesk دارند. جست‌وجو Context Store را زد، Zendesk و Stripe را کنار هم گذاشت، و پنج نفر را برگرداند.

درس MCP: تعداد ابزار را کوچک نگه دار. برای اجرای کانکتور دو ابزار اصلی: describe برای schema پرس‌وجو، و execute برای read و write و delete. سر دیگر طیف این بود که برای هر موجودیت و هر اکشن هر کانکتور یک ابزار MCP بسازند. به‌جایش کشف مرحله‌ای و کم کردن متنی که داخل توضیح ابزار می‌ریزد. گفت این به کارایی سرور MCP کمک کرده.

OAuth را راه عملی ورود به خود سرور MCP دانست. مثال انتروپیک: دکمهٔ اتصال، جریان OAuth، ورود به Airbyte، پذیرفتن دسترسی. گفت سازوکارهای دیگر، از جمله bearer، با اسپک و کلاینت‌های اصلی سخت جلو می‌رود. در ثبت کانکتور سفارشی انتروپیک جایی برای bearer ندیده و پیش‌فرض OAuth است. کاربر هم سشن طولانی می‌خواهد، بیشتر شبیه اپ موبایل تا وب‌اپ که چند بار لاگین بخواهد. سشن آفلاین و طولانی را جدا از وب‌اپ و با چرخهٔ عمر خودش نگه می‌دارند.

elicitation را راه اسپک برای گرفتن ورودی از کاربر دانست. form mode را برای دادهٔ حساس مثل رمز API مناسب ندانست. URL mode را تازه و نزدیک به کاری دانست که خودشان می‌کنند: لینک، ویجت انتخاب موجودیت، و OAuth سرویس سوم مثل HubSpot. مشکل را پشتیبانی کلاینت‌ها گفت. Claude Desktop در مثال گفت URL mode elicitation را ندارد. برگشتند به لینک خودشان و آن بخش اسپک را برای این کار استفاده نکردند.

CLI را طرف فنی‌تر و در بعضی کارها قوی‌تر خواند. همان سؤال کانکتورها این بار اسکیل CLI را لود کرد و CLI را صدا زد. همان سؤال پنج مشتری هم با CLI به Context Store رفت و گفت همان پنج کاربر برگشت.

طراحی CLI برای ایجنت، نه برای انسان. اول: JSON داخل و JSON بیرون. فلگ برای انسان قشنگ است. ورودی پیچیده را ایجنت با JSON مستقیم‌تر می‌سازد تا با حدس فلگ. خروجی JSON به پایپ یونیکس می‌رسد، از جمله jq برای بریدن جواب دراز. دوم: قرارداد یکسان. اسم بعد فعل، همه‌جا. connectors list و connectors create، و workspace list به همان شکل. اگر ایجنت بارها همان فرمان غلط را زد، همان را قرارداد کن. آن تکرار یعنی راه درست به اندازهٔ کافی آشکار نیست. سوم: اسکیل با خود CLI بیاید، وگرنه ایجنت نمی‌فهمد CLI نصب‌شده وجود دارد. توضیح اسکیل وقتی سؤال دربارهٔ کانکتور است ابزار را بالا می‌آورد. جزئیات فرمان را در فایل‌های reference داخل پوشهٔ اسکیل بگذار تا همهٔ سند اول کار داخل زمینه نرود. چهارم: احراز هویت تعاملی نه. ایجنت کسی را پای ترمینال ندارد که به پرامپت جواب بدهد. فلگ، متغیر محیط، یا فایل پیکربندی. CLI انسانی که بنشیند و سؤال بپرسد، ایجنت را همان‌جا نگه می‌دارد.

مقایسه: اسپک MCP یکدست پیاده نشده. جدا از اسپک، Claude را دارای سقف دو کیلوبایت روی توضیح سرور و توضیح فراخوانی ابزار دانست. سقف مدت اجرای ابزار را هم گفت، بدون عدد، و کار طولانی را روی MCP سخت‌تر خواند. MCP میزبانی‌شده همیشه به‌روز است. CLI نسخه‌بندی و به‌روز ماندن بسته را سخت‌تر دارد. نبودن آن سقف‌ها روی CLI هم می‌تواند ایجنت را در حلقه بچرخاند. MCP را برای کاربر غیرفنی، پروتوتایپ، گزارش یک‌باره، و حرف زدن ابزارها با هم گذاشت. CLI را برای کاربر فنی، کار طولانی‌تر، خروجی خیلی بلند، و پایپ به فایل با tail و head.

## نکته‌های کلیدی

- دو ابزار اجرا، describe و execute، به‌جای یک ابزار برای هر اکشن هر کانکتور
- اگر ایجنت یک فرمان غلط را تکرار کرد، همان را قرارداد کن
- پرامپت تعاملی ایجنت را متوقف می‌کند. JSON و اسکیل مرحله‌ای جایگزین فلگ و سند کامل است
- Claude را دارای سقف دو کیلوبایت روی توضیح سرور و ابزار دانست. URL elicitation را Claude Desktop در مثال نداشت
- پلتفرم را روزی بیش از ده بار در حال تغییر گفت. هر دو رابط لایهٔ نازک روی OpenAPI هستند
